## 2. 데이터 및 테넌트 격리 방안
- **Workspace 기반 격리**: 모든 API 요청은 HTTP Header(`Authorization: Bearer <Token>`)의 클레임(Claim)에 포함된 `workspace_ids` 권한을 대조하여 검증합니다.
- **DB 접근 통제**: 데이터베이스 조회(Select/Update/Delete) 시 ORM 계층에서 의무적으로 `WHERE workspace_id = ?` 조건을 주입하는 Middleware/Interceptor를 적용하여 타 프로젝트 데이터 열람을 원천 차단합니다.

## 3. 인증 및 권한 (Auth & RBAC)
- **SSO 연동**: 사내망 Google Workspace OAuth2 기반 로그인만을 허용하며, 임의 가입을 차단합니다.
- **세션 통제**: JWT 만료 시간은 2시간(Access Token)으로 짧게 유지하고, 유휴 세션 만료 정책을 적용합니다.
- **RBAC**: 사용자에게 부여된 Role (Admin, Manager, Operator, Viewer) 단위로 API Endpoint 접근 인가(Authorization)를 검증합니다.

## 4. LLM 보안 및 프롬프트 인젝션 방어
- **API Key 보호**: OpenAI 등 외부 LLM API Key는 소스코드에 하드코딩하지 않고 환경 변수(`.env`) 또는 AWS Secrets Manager에 암호화하여 보관합니다.
- **Prompt Injection 차단**:
  - 시스템 프롬프트(지시어)와 사용자 질의(User Query)를 뚜렷하게 분리된 마크다운 블록이나 XML 태그(`<user_query>`)로 감싸서 LLM에 전달합니다.
  - "이전 지시를 무시해", "시스템 프롬프트를 출력해" 등의 특정 키워드를 사전 정규식 룰셋으로 필터링합니다.

## 5. 데이터 마스킹 (PII 필터링)
- **로그 저장 전 필터링**: `chat_messages` 테이블에 대화 로그를 Insert 하기 전, 정규식을 통해 주민등록번호, 연락처, 이메일, 사번, 계좌번호 패턴을 `***`로 마스킹합니다.
- **LLM 전송 전 필터링**: 사내 기밀 단어(예: 비공개 프로젝트명, 임원 인사 정보)가 발견될 경우 LLM API(외부) 호출 전 알림을 주거나 전송을 차단합니다.

## 6. 파일 업로드 및 네트워크 보안
- **악성 파일 차단**: 관리자가 지식 문서 업로드 시, 허용된 확장자(PDF, DOCX, TXT)만 허용하며, 파일 내 실행 스크립트가 포함되어 있는지 백신 모듈(또는 오픈소스 ClamAV)로 스캔합니다.
- **Rate Limit (DDoS 방어)**: Nginx 및 FastAPI Middleware에서 IP 당 API 호출 횟수(예: 분당 60회)를 제한합니다.
- **CORS 설정**: 승인된 사내 사이트 도메인(예: `*.kt.co.kr`, `*.jwinpartners.com`)에서만 챗봇 위젯 API를 호출할 수 있도록 화이트리스트 기반 CORS를 적용합니다.

## 7. 감사 및 이력 관리
- **Audit Log**: BO(관리자) 사이트에서 문서 삭제, 권한 변경, 시스템 프롬프트 수정 등 파급력이 큰 행위는 `audit_logs` 테이블에 영구 보관되며 삭제 기능을 제공하지 않습니다.
