## 2. 주요 변경 사항 요약 (차이점)

| 영역 | 기존 설계 (v0.2) | 신규 설계 (v1.0 Multi-Tenant) | 변경 영향도 파악 |
|---|---|---|---|
| **아키텍처** | 단일 DB 구성, 탄소중립 전용 지식 처리 | `Workspace` 단위 논리적 격리(Tenant) 도입 | API Gateway 라우팅 로직 변경, 각 API마다 `workspace_id` 검증 로직 추가 (High) |
| **데이터 모델** | `graphrag_sources`, `chat_logs` 등의 플랫 구조 | 모든 핵심 테이블 최상단에 `workspaces` 테이블 연결 및 FK 지정 | 전체 테이블 스키마 재생성 수준의 DDL 변경 필요 (High) |
| **권한 구조** | `ROLE_ADMIN`, `ROLE_EMPLOYEE` (2단계) | `System Admin`, `Workspace Admin`, `Operator` 등 5단계 RBAC 도입 | 관리자 사이트의 메뉴 및 버튼 단위 권한 제어 코딩 복잡도 증가 (High) |
| **관리자 UI** | 챗봇 프롬프트, 테스트, 권한 관리 등 | 통합 대시보드 및 Workspace별 분리 관리 UI 신설 | BO UI 프레임워크에 "현재 선택된 Workspace Context" 전역 상태 추가 필요 (Medium) |
| **검색(RAG)** | 텍스트 청킹 + Vector 유사도 검색 중심 | LLM 기반 엔티티(Entity), 관계(Relation) 그래프 추출 결합 (GraphRAG) | 인덱싱 소요 시간 및 파이프라인(Celery 등) 인프라 비용 증가 (High) |

---

## 3. 기존 산출물 대비 신규/삭제 내역

1. **[NEW] Workspace 및 계정 권한 모델**
   - 사내 여러 팀이 플랫폼을 나눠 써야 하므로 프로젝트(Workspace) 생성 기능이 핵심 추가되었습니다.
2. **[NEW] System Admin 대시보드**
   - 플랫폼의 전체 리소스(LLM 토큰, 용량)를 모니터링하기 위해 최상위 관리자 전용 화면이 추가되었습니다.
3. **[UPDATE] API 명세서 전면 개편**
   - 기존 `/api/v1/sources`와 같은 단일 구조에서 `/api/v1/workspaces/{ws_id}/sources` 형태로 모든 RESTful Endpoint의 스펙이 변경되었습니다.
4. **[DELETE] 단일 로그인 및 통합 권한 테이블**
   - 탄소중립 관리자만 상정했던 `admin_users` 단일 구조는 폐기되고, `workspace_users`를 통한 M:N(다대다) 매핑 구조로 전환되었습니다.
