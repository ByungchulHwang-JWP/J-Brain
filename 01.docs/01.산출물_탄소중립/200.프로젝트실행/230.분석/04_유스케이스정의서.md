## 2. 액터 (Actor) 정의
본 플랫폼은 멀티 프로젝트 환경을 지원하기 위해 다음 6가지 액터로 세분화됩니다.

1. **System Admin (시스템 관리자)**: 플랫폼 전체를 총괄. 신규 Workspace(프로젝트) 생성 및 최상위 권한 부여 담당.
2. **Workspace Admin (프로젝트 관리자)**: 특정 Workspace(예: 탄소중립플랫폼)의 마스터. 챗봇 기본 설정 및 팀원 역할 할당 담당.
3. **Knowledge Manager (지식 관리자)**: Workspace 내의 문서 업로드, FAQ 작성, 인덱싱(GraphRAG) 작업 수행 담당.
4. **Operator (운영 담당자)**: 대화 로그, 사용자 피드백, 미응답(Fallback) 질문 모니터링 및 품질 개선안 도출 담당.
5. **Viewer (조회 전용 사용자)**: 각종 통계 및 대시보드 조회만 가능한 담당자.
6. **End User (일반 사용자)**: FO 사이트에 접속하여 챗봇을 이용하는 실제 고객 또는 사내 임직원.

## 3. 핵심 유스케이스 상세

### 3.1 [UC-01] 신규 프로젝트(Workspace) 셋업
| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-01 |
| **액터** | System Admin |
| **사전조건** | 사내 신규 프로젝트(예: DPPA 정산)에서 챗봇 도입을 요청함. |
| **기본 흐름** | 1. System Admin이 관리자 사이트 로그인 후 'Workspace 관리' 메뉴 진입.<br>2. 신규 Workspace 생성(ID, 이름, 설명 입력).<br>3. 해당 프로젝트의 PM(사내망 이메일)을 'Workspace Admin'으로 지정.<br>4. 저장 및 승인 처리. |
| **결과** | 신규 Workspace가 활성화되며, 지정된 PM이 해당 Workspace 관리자로 로그인 가능해짐. |

### 3.2 [UC-02] 챗봇 기초 설정 및 배포 준비
| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-02 |
| **액터** | Workspace Admin |
| **사전조건** | System Admin으로부터 Workspace Admin 권한을 부여받음. |
| **기본 흐름** | 1. Workspace Admin이 로그인하여 자신의 Workspace 대시보드 진입.<br>2. '챗봇 설정' 메뉴에서 챗봇 이름, 테마 색상, 웰컴 메시지 작성.<br>3. 초기 화면에 노출될 '추천 질문' 3~5개 등록.<br>4. 시스템 프롬프트(어조, 답변 원칙) 작성 및 저장. |
| **결과** | FO 챗봇 위젯이 렌더링될 때 해당 설정값과 추천 질문이 표출됨. |

### 3.3 [UC-03] 지식 소스(문서) 업로드 및 인덱싱 실행
| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-03 |
| **액터** | Knowledge Manager |
| **사전조건** | 챗봇이 답변할 도메인 문서(PDF/DOCX)가 준비되어 있음. |
| **기본 흐름** | 1. Knowledge Manager가 '지식 관리 > 문서 관리' 메뉴 진입.<br>2. 준비된 문서 파일 업로드 및 카테고리 지정.<br>3. 목록에서 해당 문서의 [인덱싱 실행] 버튼 클릭.<br>4. 백그라운드에서 GraphRAG 파이프라인(청킹, 벡터 임베딩, 엔티티 추출) 실행.<br>5. 진행률(%) 바를 통해 작업 완료 확인. |
| **예외 흐름** | - **파일 손상**: 업로드 중 파싱 불가 시 'FAILED' 상태 처리 후 에러 메시지(Audit Log) 노출.<br>- **재인덱싱**: 기 인덱싱된 문서 재실행 시 기존 Chunk/Entity 데이터 덮어쓰기 안내 모달 표출. |
| **결과** | 문서의 지식이 Vector 및 Graph DB에 저장되어 챗봇 답변의 근거로 활용될 준비 완료. |

### 3.4 [UC-04] 지식 검색 품질 테스트
| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-04 |
| **액터** | Knowledge Manager, Operator |
| **사전조건** | 문서 업로드 및 인덱싱이 최소 1건 이상 완료됨. |
| **기본 흐름** | 1. '테스트/프롬프트 > 챗봇 테스트' 메뉴 진입.<br>2. Sandbox 챗봇 창에서 예상 질문 입력 및 전송.<br>3. 디버그 모드를 On으로 설정하여 응답 시간, Token 사용량 확인.<br>4. 답변에 맵핑된 문서 출처(Evidence Score) 및 추출된 Graph Relation 추적 내역 검토. |
| **결과** | 답변 품질 및 근거 맵핑의 정확성을 실제 배포 전 검증 완료. |

### 3.5 [UC-05] FO 챗봇 질의응답 및 피드백 (End User)
| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-05 |
| **액터** | End User |
| **사전조건** | 사용자가 프로젝트 FO 사이트(예: 탄소중립플랫폼)에 접속 중임. |
| **기본 흐름** | 1. 화면 우측 하단의 챗봇 위젯 클릭하여 창 열기.<br>2. 대화창에 도메인 관련 질문 입력.<br>3. 챗봇이 Typing 애니메이션과 함께 답변 및 출처(칩 형태) 제공.<br>4. 사용자가 출처 칩을 클릭하여 원본 문서명 확인.<br>5. 사용자가 답변 아래의 '좋아요(👍)' 또는 '싫어요(👎)' 클릭 후 간략한 의견 제출. |
| **예외 흐름** | - **지식 부재**: 시스템이 관련된 Chunk를 찾지 못한 경우 사전에 정의된 Fallback 메시지("해당 지식을 찾을 수 없습니다...") 표출.<br>- **세션 만료**: 브라우저 종료 후 재진입 시 챗봇 초기화 (또는 로컬 스토리지 기반 최근 내역 복원). |
| **결과** | 사용자는 궁금증을 해소하고, 관리자는 대화 이력과 피드백 로그를 축적함. |

### 3.6 [UC-06] 미응답 질문 모니터링 및 개선
| 항목 | 내용 |
|---|---|
| **유스케이스 ID** | UC-06 |
| **액터** | Operator, Knowledge Manager |
| **사전조건** | 사용자가 질의했으나 Fallback 처리된 이력이 다수 존재함. |
| **기본 흐름** | 1. Operator가 '사용 로그 조회' 메뉴 진입 후 '미응답(Fallback) 필터' 적용.<br>2. 빈번하게 발생하는 미응답 질문 리스트(엑셀 다운로드 등) 취합.<br>3. Knowledge Manager에게 해당 질문에 대한 FAQ 작성 또는 추가 문서 업로드(인덱싱) 요청.<br>4. Knowledge Manager가 관련 지식 보강 후 챗봇 테스트 수행. |
| **결과** | 지속적인 지식 보강을 통해 챗봇의 미응답률 감소 및 정답률(품질) 향상. |
