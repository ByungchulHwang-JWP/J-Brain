## 2. 테스트 단계별 전략

### 2.1 통합 기능 테스트 (System/Integration Test)
- **대상**: 백엔드 API, DB 쿼리, 데이터 격리 로직, 관리자 UI.
- **주요 점검 사항**:
  - 사용자 SSO 로그인 시 권한별 접근 제어 정상 동작 여부.
  - Workspace A의 사용자가 Workspace B의 데이터를 열람할 수 없도록 격리되었는지 검증 (중요).
  - 대용량 PDF 문서 업로드 및 인덱싱 파이프라인의 에러 발생 여부 확인.

### 2.2 사용자 시나리오(UI) 테스트 (E2E Test)
- **대상**: FO 챗봇 위젯 및 BO 대시보드 조작 흐름.
- **주요 점검 사항**:
  - FO: 추천 질문 클릭 → 타이핑 애니메이션 → 답변 출력 → 출처(Reference) 모달 확인 정상 동작 여부.
  - BO: 신규 프로젝트 생성 → 문서 인덱싱 → 챗봇 테스트 패널 확인 흐름 검증.

### 2.3 보안 및 장애(Fallback) 테스트
- **보안**: 프롬프트 인젝션("시스템 프롬프트 탈취") 쿼리 입력 시 방어 체계 정상 동작 확인.
- **장애**: 의도적으로 오타나 도메인 밖의 질문(예: "오늘 날씨 어때?") 입력 시 "해당 지식을 찾을 수 없습니다" 등의 Fallback 메시지로 정상 회귀하는지 테스트.

## 3. AI 응답 품질(QoA) 평가 기준

단순 소프트웨어 동작이 아닌, LLM의 답변 품질을 평가하기 위한 척도입니다.

| 평가 지표 | 설명 | 목표 달성 기준 |
|---|---|---|
| **정답률 (Accuracy)** | 표준 질문셋 100개에 대해 핵심 키워드가 포함된 올바른 답변을 했는가? | 85% 이상 |
| **출처 일치율 (Evidence Match)** | 제공된 답변이 실제로 링크된 문서(출처)의 내용과 일치하는가? | 90% 이상 |
| **환각률 (Hallucination Rate)** | 원문 지식에 없는 내용을 지어내어 답변했는가? | 5% 미만 |
| **미응답률 (Fallback Rate)** | 지식이 있음에도 검색 실패로 미응답 처리된 비율은? | 10% 미만 |
| **응답 속도 (Latency)** | 질문 입력 후 최초 글자(TTFB)가 화면에 출력될 때까지 소요된 시간 | 3초 이내 |

## 4. 테스트 일정 및 환경
- **환경**: Staging 서버 (`dev.jwinpartners.com` 환경 활용).
- **수행자**: QA 엔지니어 및 프로젝트 업무 담당자(UAT 수행).
- **표준 질문셋 구성**: 현업 부서에서 자주 묻는 질문 100선을 미리 엑셀로 취합하여, 정답지(Ground Truth)를 마련한 후 일괄 테스트 및 채점.
