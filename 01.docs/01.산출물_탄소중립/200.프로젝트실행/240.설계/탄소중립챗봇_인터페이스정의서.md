## 2. 관리자(BO) 구글 SSO 로그인 프로세스

관리자(Admin) 및 직원(Employee)이 관리자 사이트에 접근하기 위해 구글 SSO 인증을 거치고, 서버로부터 역할(RBAC) 기반 JWT 토큰을 발급받는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor Admin as 관리자(Admin)
    participant BO as BO Front (React/Vue)
    participant AuthAPI as Backend (FastAPI)
    participant Google as Google OAuth2 서버
    participant DB as DB (admin_users, sys_roles)

    Admin->>BO: 로그인 버튼 클릭 (Google SSO)
    BO->>Google: OAuth2 인증 요청 (Redirect)
    Google-->>Admin: 구글 로그인창 제공
    Admin->>Google: 계정 선택 및 로그인
    Google-->>BO: 인증 코드 (Auth Code) 반환
    
    BO->>AuthAPI: POST /api/v1/auth/login (Auth Code 전달)
    AuthAPI->>Google: 토큰 및 유저 정보(Email) 요청
    Google-->>AuthAPI: 유저 프로필 (Email, Name 등) 반환
    
    AuthAPI->>DB: 등록된 관리자 여부 확인 (SELECT email FROM admin_users)
    DB-->>AuthAPI: 사용자 정보 및 role_id 반환
    
    alt 미등록 사용자
        AuthAPI-->>BO: 401 Unauthorized (접근 권한 없음)
        BO-->>Admin: "관리자 승인이 필요합니다" 안내
    else 등록된 사용자
        AuthAPI->>AuthAPI: JWT Access Token 생성 (payload: email, role_id)
        AuthAPI->>DB: 최근 로그인 시간(last_login_at) 업데이트
        AuthAPI-->>BO: 200 OK (JWT Token)
        BO->>BO: 토큰 로컬 스토리지 저장 및 라우팅
        BO-->>Admin: 대시보드 화면 노출
    end
```

## 3. 사용자(FO) 챗봇 질의응답 프로세스 (GraphRAG)

사용자가 챗봇에 자연어로 질문을 입력하고, 백엔드에서 벡터 검색 및 지식 그래프 검색을 융합(Hybrid)하여 LLM 답변을 스트리밍으로 반환하는 흐름입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 일반 사용자
    participant FO as 챗봇 위젯 (FO)
    participant ChatAPI as Backend API
    participant GraphRAG as GraphRAG Pipeline
    participant DB as Vector/Graph DB
    participant LLM as OpenAI (GPT-4o)

    User->>FO: 질문 입력 ("배출권거래제 대상은?")
    FO->>ChatAPI: POST /api/v1/chat (query, session_id)
    
    ChatAPI->>DB: 세션 유효성 및 이전 대화 이력 조회
    DB-->>ChatAPI: 최근 대화 Context 반환
    
    ChatAPI->>GraphRAG: 파이프라인 호출 (질문 + 이력)
    
    par 벡터 검색 (Semantic)
        GraphRAG->>DB: 사용자 질문 임베딩 후 벡터 유사도 검색 (graphrag_chunks)
    and 그래프 검색 (Relation)
        GraphRAG->>DB: 질문 내 핵심 Entity 매칭 후 인접 엣지 순회 (graphrag_relations)
    end
    DB-->>GraphRAG: 하이브리드 검색 결과 (Chunk 텍스트 및 연관 그래프 반환)
    
    GraphRAG->>GraphRAG: Context Assembler (검색 결과 조립)
    
    GraphRAG->>LLM: 프롬프트 + Context + 질문 전송 (Streaming 요청)
    
    loop 스트리밍 응답
        LLM-->>GraphRAG: Token Stream
        GraphRAG-->>ChatAPI: SSE Stream (Server-Sent Events)
        ChatAPI-->>FO: Chunk 단위 데이터 전송
        FO->>User: 타이핑 효과로 화면에 텍스트 노출
    end
    
    GraphRAG->>GraphRAG: 출처(Evidence) 메타데이터 병합
    GraphRAG-->>ChatAPI: 최종 응답 완료 시그널 및 출처 정보 전달
    ChatAPI->>DB: 질문, 답변 내용, 토큰 사용량 저장 (chat_logs, chat_history)
    ChatAPI-->>FO: [Done] 시그널 및 출처(Evidence) 목록
    FO->>User: 답변 하단에 출처(칩 형태) 렌더링
```

## 4. 관리자(BO) 문서 등록 및 비동기 인덱싱 프로세스

관리자가 방대한 분량의 PDF 문서를 업로드하면 백엔드에서 백그라운드 태스크로 청킹, 임베딩, 그래프 엔티티 추출을 수행하는 흐름입니다.

```mermaid
sequenceDiagram
    autonumber
    actor Admin as 관리자(Admin)
    participant BO as BO Front
    participant AdminAPI as Backend API
    participant Worker as Background Task (Celery/AsyncIO)
    participant LLM as OpenAI API (Extraction)
    participant DB as Vector/Graph DB

    Admin->>BO: 파일 업로드 및 [등록] 클릭
    BO->>AdminAPI: POST /api/v1/admin/sources (Multipart)
    AdminAPI->>DB: graphrag_sources 테이블 INSERT (상태: UPLOADED)
    AdminAPI-->>BO: 200 OK (Source ID)
    
    Admin->>BO: 목록에서 [인덱싱 실행] 클릭
    BO->>AdminAPI: POST /api/v1/admin/sources/{id}/index
    
    AdminAPI->>DB: index_jobs 테이블 레코드 생성 (상태: PENDING)
    AdminAPI->>Worker: 인덱싱 백그라운드 태스크(비동기) 트리거
    AdminAPI-->>BO: 200 OK (비동기 작업 시작 알림)
    
    rect rgb(240, 248, 255)
        Note over Worker, DB: --- 백그라운드 프로세스 ---
        Worker->>DB: Job 상태 업데이트 (PROCESSING)
        Worker->>Worker: PDF 텍스트 추출 및 Chunking (예: 1000자)
        
        loop 각 Chunk 단위 처리
            Worker->>LLM: 1. Embedding 요청
            LLM-->>Worker: 벡터 데이터 반환
            
            Worker->>LLM: 2. Entity / Relation 추출 요청 (도메인 프롬프트)
            LLM-->>Worker: JSON 형태의 엔티티/관계 데이터 반환
            
            Worker->>DB: graphrag_chunks, entities, relations 저장
            Worker->>DB: index_jobs의 processed_chunks 카운트 증가
        end
        Worker->>DB: Job 상태 업데이트 (COMPLETED) 및 sources 상태 변경
    end
    
    loop 폴링 (Polling)
        BO->>AdminAPI: GET /api/v1/admin/sources (상태 확인)
        AdminAPI-->>BO: 인덱싱 진행률 및 상태 반환
    end
    BO->>Admin: "인덱싱이 완료되었습니다." 알림
```
