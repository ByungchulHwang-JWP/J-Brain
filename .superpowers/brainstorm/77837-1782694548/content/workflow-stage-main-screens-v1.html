각 단계 선택 시 이동하는 메인 화면

아래는 단계별 상세 화면의 첫 화면 구조입니다. 모든 상세 화면은 “상태 요약 → 해야 할 일 → 입력/검수 영역 → 완료 조건 → 다음 단계 이동” 패턴을 공통으로 사용합니다.

1. 기반 설정 메인

화면 목적: 프로젝트를 시작하기 위한 고객사/서비스/환경/연계 기준을 확정합니다.

기반 설정
프로젝트 정보 카드
고객사, 서비스명, 환경, 담당자, 목표 배포일
완료 조건
6개 중 4개 완료
누락: 메뉴/API 정보, Runtime 환경

주요 이동: 프로젝트 설정, 고객사/서비스 정보, 메뉴/화면/API 정보 관리

2. 지식 준비 메인

화면 목적: 고객 자료를 Source로 등록하고 벡터화/분석 상태를 확인합니다.

지식 준비
Source 24건
벡터화 성공 21건
오류 1건
검색 가능 88%
Source 목록 / 업로드 / URL 등록 / 벡터화 작업 재실행

주요 이동: Source 관리, 지식 업로드, 벡터화 작업 현황, 검색 테스트

3. 의도 설계 메인

화면 목적: 사용자가 물어볼 의도를 정의하고 각 Intent가 어떤 Action으로 이어지는지 설계합니다.

의도 설계
Intent 목록

주요 이동: Intent 관리, Intent 상세, Action 관리

4. 질문 커버리지 메인

화면 목적: Intent별 질문패턴 수와 표현 다양성을 점검하고 부족한 패턴을 보강합니다.

Coverage Heatmap

주요 이동: Intent 상세, 질문패턴 편집, Pack 검증 질문

5. 용어 사전 메인

화면 목적: Entity와 Synonym을 정리하여 사용자의 표현 차이를 흡수합니다.

용어 사전
Entity 목록

주요 이동: Entity/Synonym 관리, Intent Entity 연결

6. 답변 근거 메인

화면 목적: FAQ와 Source 문서를 SEARCH_DOC Action의 근거로 연결합니다.

주요 이동: FAQ 관리, Source 관리, Runtime QA

7. 실행 연결 메인

화면 목적: Intent 결과가 화면 이동, 검색, API/SQL 조회 등 어떤 실행으로 연결되는지 관리합니다.

화면 목적: 품질검증, Runtime 시뮬레이션, Pack Build, 배포, 운영 분석/개선까지 이어지는 후반 단계를 관리합니다.

추천 UX 원칙

각 단계 화면은 단순 등록 화면이 아니라 “단계 작업실”처럼 구성합니다. 운영자는 먼저 상태와 부족 항목을 보고, 바로 아래에서 입력/검수/대량 작업을 수행한 뒤, 완료 조건을 충족하면 다음 단계로 넘어갑니다.
