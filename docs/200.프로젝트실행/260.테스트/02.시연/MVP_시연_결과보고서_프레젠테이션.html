LLM 의존도 탈피 및 아키텍처 분리 전략 실증

🚨

배경 (As-Is)

• 보안 규제: 폐쇄망 환경의 외부망 연동 및 데이터 반출 불가

• 비용 부담: 자체 On-Premise LLM 구축/운영의 막대한 리소스 소모

• 환각 오류: 생성형 AI 특유의 할루시네이션 문제로 실무 적용 리스크

➔
💡

해결책 (To-Be)

• 경량화 엔진: LLM에 전적으로 의존하지 않는 J-Brain 자체 NLU 공통 엔진 활용

• 아키텍처 분리: 무거운 공통 플랫폼 엔진과 서비스별 두뇌 팩(Intent Pack) 완벽히 분리

• 유연성: 도메인 지식만 가볍게 패키징

➔
✅

MVP 검증 결과

• 보안 입증: 외부망(Factory) Pack 생성 후 내부망(Runtime) Import 파이프라인 구현 성공

• 성능 확인: 폐쇄망 제약을 완벽히 준수하면서도 외부 API 없이 높은 NLU 추론 정확도 확보

Intent Factory 파이프라인 작동 검증

공장(Factory) 파이프라인 전체를 UI로 구현

  • Pack 구성 요소 완비:
    • Intent, Entity/Synonym(유의어 사전), Action, FAQ 등 장표에서 기획했던 모든 JSON 구성 요소를 J-Brain 관리자 웹 화면에서 완벽하게 제어 가능
  • Pack 생성 자동화:
    • 지식 업로드 ➔ AI 의도 자동 추출 ➔ 수동 Action 연결 ➔ 무결성 검증 ➔ 버전업 빌드(v0.1.0) 원스톱 툴 완성
👉 시연 포인트 연계: `[3. 의도 설계]` ~ `[5. Pack 검증 및 빌드]` 단계에서 이 강력한 관리자 경험(Admin UX)을 직접 눈으로 확인하실 수 있습니다.

보안 및 운영 원칙 적용

내부 데이터 보호 및 시스템 투명성 확보

  • 데이터 유출 차단 (하이브리드 RAG):
    • 내부 지식 문서와 FAQ는 철저히 폐쇄망(Runtime) 내에서만 검색
    • 외부 LLM API 호출을 최소화하는 하이브리드 RAG 정책 적용 완료
  • White-box 기반의 모니터링 체계:
    • 챗봇의 답변 도출 과정, 점수(Score) 및 매칭된 Intent를 명확하게 들여다볼 수 있는 [Runtime QA 대화 테스트] 도구 탑재
    • 블랙박스형 AI의 한계를 극복하고 운영 안정성 대폭 향상

향후 계획 (Next Steps)

성공적인 MVP 시연을 기점 삼아 전사적 확산 추진

  • 1. 시연 완료 후 (Post-Demo):
    • 탄소중립플랫폼 파일럿 피드백 수렴 및 UI/UX 디테일 폴리싱
  • 2. 수평 전개 (Horizontal Roll-out):
    • HR, 재무, IT Helpdesk 등 사내 타 시스템으로 신규 프로젝트(Tenant)를 생성하여 챗봇 적용 범위 확대
  • 3. 시스템 고도화 과제:
    • 1차 제외 범위였던 동적 DB 조회(Text-to-SQL) 및 복합 Action(데이터 등록/수정) 기능에 대한 R&D 본격 착수
