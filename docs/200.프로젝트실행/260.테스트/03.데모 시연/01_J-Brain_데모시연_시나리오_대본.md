> **발표자(Presenter):** PM (또는 시연 담당자)
> **소요 시간:** 약 10~15분

- **백업 파일:** `01_백업데이터/` 폴더 내에 `J-Brain_Manual.txt`, `03_J-Brain_운영_매뉴얼_및_가이드.md` 준비 확인

## 3단계: 의도(Intent) 설계 (05:00 ~ 08:00)

**[화면 액션]**
- 3단계 **[의도 설계]** 대시보드로 이동
- 상단의 **[Auto Discovery 후보 검토]** 영역 진입
- 시스템이 앞서 업로드한 `J-Brain_Manual.txt`와 `03_J-Brain_운영_매뉴얼`을 AI가 분석하여 도출해 둔 **총 84건의 후보군**(Intent 14건, FAQ 14건, Entity 14건, Action 14건 등)이 리스트업된 것을 화면에 보여줌
- **[전체 후보 일괄 승인(적용)]** 버튼을 클릭하여 84건을 단숨에 실제 DB로 적용
- 다시 **[Intent 관리]** 화면으로 돌아와, '시스템 관리', '벡터화 현황 조회', '매뉴얼 검색' 등 문서 기반의 다양한 Intent들과 파생된 수많은 예상 질문들이 **자동으로 최대치로 생성되어 꽉 채워진 화면**을 시연

**🗣️ 발표 멘트:**
> "이곳은 챗봇의 두뇌인 '의도(Intent)'를 기획하는 팩토리 공간입니다. 기존에는 수많은 기획자와 현업이 모여 엑셀로 예상 질문을 하나하나 쥐어짜내며 설계해야 했지만, J-Brain은 다릅니다. 
> 
> 방금 업로드한 방대한 2개의 매뉴얼 문서를 시스템이 스스로 완독하고 분석한 결과, 보시는 것처럼 무려 84건의 핵심 의도(Intent), FAQ, 필수 업무 용어(Entity)를 **자동으로 도출(Auto Discovery)** 해두었습니다. 
> 
> 운영자는 단지 **'전체 승인' 버튼 한 번만 누르면 됩니다.** 보시다시피 클릭 한 번에 매뉴얼 내의 '운영 현황 조회', '권한 관리', '팩 배포' 등 14가지가 넘는 세부 의도들과 그에 파생되는 수십 개의 예상 질문들이 챗봇의 두뇌에 단 1초 만에 최대로 구축(Factory)되었습니다. 이것이 J-Brain만의 압도적인 지식 자동화 기술입니다."

## 4단계: FAQ & Action 연결 (08:00 ~ 10:00)

**[화면 액션]**
- 방금 만든 4개의 Intent 상세 설정 창에서 각각 **[Action 연결]** 탭을 클릭하여 상세 정보를 입력합니다.

**1. [유형 1: 지식/문서 검색] `매뉴얼_검색` Intent**
- **Action 종류:** `문서/FAQ 검색 (RAG)` 선택
- **검색 대상(Source):** `전체 문서` 또는 업로드한 `J-Brain_Manual.txt` 지정
- **응답 템플릿:** "요청하신 매뉴얼 내용입니다: \n\n {rag_result}"
- *설명: 환각 없이 오직 문서 내에서만 답을 찾도록 제한합니다.*

**2. [유형 2: REST API 연동] `사용자_통계_API` Intent**
- **Action 종류:** `API/SQL Template 실행` 선택
- **연동 방식:** `REST API` 선택
- **API Method & URL:** `GET` / `/api/v1/projects/statistics/users` (프로젝트 통계 API 연동)
- **응답 템플릿:** "현재 J-Brain 프로젝트에 접속중인 통계입니다: \n\n {api_result}"
- *설명: LLM이 데이터를 지어내지 못하게 사내 통계 API를 직접 호출하여 실시간 데이터를 가져옵니다.*

**3. [유형 3: SQL 쿼리 직접 조회] `사용자_목록_SQL` Intent**
- **Action 종류:** `API/SQL Template 실행` 선택
- **연동 방식:** `SQL Query` 선택
- **쿼리 템플릿:** `SELECT email, role FROM admin_users WHERE is_active = true;`
- **응답 템플릿:** "DB에 등록된 활성 사용자 명단입니다: \n\n {sql_result}"
- *설명: 사내 DB에 직접 쿼리를 수행하여 정확한 로우(Row) 데이터를 반환합니다.*

**4. [유형 4: 메뉴/화면 이동] `보고서_작성_이동` Intent**
- **Action 종류:** `지정 URL 이동 (Route)` 선택
- **이동 경로(URL):** `/report/write`
- **응답 템플릿:** "네, 월간 보고서 기안 페이지로 안내해 드리겠습니다."
- *설명: 사용자가 복잡한 뎁스의 메뉴를 찾을 필요 없이 바로 목적지로 라우팅합니다.*

**🗣️ 발표 멘트:**
> "의도를 파악했다면, 챗봇이 '어떤 행동(Action)'을 해야 할지 지정해야 합니다. J-Brain의 가장 큰 차별점이 바로 이 부분입니다. 단순히 생성형 AI가 그럴싸한 답변을 지어내는(환각) 것이 아니라 완벽하게 통제된 4가지 행동을 수행합니다."
> "RAG를 활용한 **문서 검색**, 사내 시스템과 통신하는 **REST API 호출**, 데이터베이스에서 즉각 데이터를 뽑아오는 **SQL 쿼리 실행**, 그리고 사용자를 목적지로 보내주는 **URL 라우팅** 입니다. 각각의 의도에 맞게 이 4가지 액션을 맵핑했습니다."

## 6단계: Runtime 시뮬레이션 (12:00 ~ 15:00)

**[화면 액션]**
- **[QA / 시뮬레이션]** 메뉴 이동 및 우측 하단 챗봇 위젯 열기
- **테스트 1 (RAG 검색 기반 매뉴얼 질의):**
  - **입력:** "J-Brain에서 미응답 분석 기능이 뭐야?"
  - **챗봇 답변:** "J-Brain의 '미응답 분석' 기능은 챗봇이 답변에 실패하거나 낮은 신뢰도를 보인 질문 목록을 추적하고 분석하는 기능입니다. 분석된 내역은 '개선 요청 관리' 메뉴로 연계되어, 다음 Pack 배포 시나리오에 신규 FAQ나 Intent 후보로 즉각 반영할 수 있도록 돕는 선순환 구조의 핵심 기능입니다."
- **테스트 2 (RAG 기반 절차 가이드):**
  - **입력:** "새로운 Pack을 배포하고 활성화하는 절차를 알려줘"
  - **챗봇 답변:** "새로운 Pack 배포 및 활성화 절차는 다음과 같습니다. 1) 'Pack Builder'에서 저장된 지식 데이터를 취합하여 배포용 팩(Draft)을 생성 및 Export 합니다. 2) 'Pack 검증' 메뉴에서 자동 검증을 수행합니다. 3) 검증된 팩을 'Pack Repository'에 Import 한 뒤, 최종 승인 및 활성화(Activate) 처리를 하면 Runtime 서버에 즉시 적용됩니다."
- **테스트 3 (액션 라우팅 - 화면 직접 이동):**
  - **입력:** "권한 관리 화면으로 가고 싶어"
  - **챗봇 답변:** "네, 권한 관리 화면으로 안내해 드리겠습니다." ➡️ (답변과 동시에 `http://localhost:5174/system/role` 페이지로 즉시 라우팅되어 화면이 전환됨을 시연)

**🗣️ 발표 멘트:**
> "마지막으로 시뮬레이션 창에서 앞서 자동 생성한 수많은 지식들이 어떻게 동작하는지 보겠습니다. '미응답 분석 기능이 무엇인지', 'Pack 배포 절차가 어떻게 되는지' 물어보면, 챗봇이 AI가 환각(거짓)으로 지어내는 것이 아니라 오직 우리가 2단계에서 업로드했던 매뉴얼 원문(Source)만을 근거로 정확하게 요약하여 답변해 줍니다."
> 
> "더 놀라운 것은 액션(Action) 통제 기능입니다. '권한 관리 화면으로 가고 싶어'라고 입력하면, 챗봇이 구구절절 설명하는 대신 지정된 라우팅 규칙(Action)에 따라 즉시 사용자의 화면을 권한 관리 페이지로 이동시켜 버립니다. 외부 LLM에 의존하지 않고 로컬 Runtime에서 완벽히 통제되는 엔터프라이즈급 챗봇의 위력입니다."
> 
> "이로써 외부망이나 보안 위험 없이, 클릭 몇 번으로 지식을 최대치로 구축하고 오직 승인된 절차대로만 동작하는 J-Brain 챗봇 구축 시연을 마치겠습니다. 감사합니다!"
