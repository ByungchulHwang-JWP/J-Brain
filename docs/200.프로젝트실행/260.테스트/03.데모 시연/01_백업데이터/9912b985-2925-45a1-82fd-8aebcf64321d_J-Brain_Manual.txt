# J-Brain 운영자 매뉴얼 v3.0

## 1. 문서 목적

이 문서는 J-Brain 관리자와 구축 담당자가 JWP Intent Factory 기반 챗봇을 실제 운영 절차에 맞게 구축, 검증, 배포, 개선할 수 있도록 작성한 운영 매뉴얼입니다.

기존 J-Brain 문서는 GraphRAG와 지식 검색 중심 설명이 많았으나, 현재 시스템은 단순 지식 챗봇을 넘어 다음 범위를 포함합니다.

- 프로젝트별 챗봇 구축 워크플로우 관리
- Source 문서 수집 및 벡터화
- Intent, Example, Entity, Synonym, FAQ, Action 관리
- DB 기반 Pack Draft 생성
- Pack Export ZIP 생성
- Runtime Pack Import, Validation, Approval, Active 전환
- Runtime QA, Intent 매칭 테스트, 미응답 분석, 개선 요청 관리

J-Brain 운영의 핵심 원칙은 “고객 내부망 Runtime에는 검증된 Pack만 반입하고, 외부 LLM/API 없이 로컬 Runtime이 Intent 매칭과 Action 실행을 수행한다”입니다.

## 2. 주요 사용자 역할

### 2.1 시스템 관리자

시스템 관리자는 메뉴 권한, 사용자, 운영 설정, 감사 로그를 관리합니다.

주요 업무는 다음과 같습니다.

- 사용자 계정 관리
- 권한 관리
- 메뉴 접근 권한 확인
- 시스템 설정 관리
- 감사 로그 확인
- 전체 프로젝트 운영 현황 확인

### 2.2 구축 PM 또는 운영 PM

구축 PM은 프로젝트 생성부터 Pack 활성화까지 전체 구축 흐름을 관리합니다.

주요 업무는 다음과 같습니다.

- 프로젝트 선택 및 상태 확인
- 12단계 구축 워크플로우 진행
- Source 수집 현황 확인
- Intent/FAQ/Action 품질 검토
- Pack 검증 결과 확인
- 승인 및 활성화 요청
- 운영 개선 항목 관리

### 2.3 지식 관리자

지식 관리자는 고객 문서, FAQ, 답변 근거를 정리합니다.

주요 업무는 다음과 같습니다.

- Source 문서 등록
- 벡터화 작업 상태 확인
- 검색 테스트 수행
- FAQ 등록 및 Pack 반영 여부 확인
- 답변 근거 Source 연결

### 2.4 Intent 설계자

Intent 설계자는 사용자의 자연어 질문을 시스템 Action과 연결하는 구조를 설계합니다.

주요 업무는 다음과 같습니다.

- Intent 등록
- Intent Example 보강
- Entity/Synonym 등록
- Intent와 Entity 연결
- Intent와 Action 연결
- 검증 질문 기준 작성

## 3. 시스템 접속 및 기본 사용

### 3.1 로그인

접속 경로는 로컬 개발 환경 기준으로 다음과 같습니다.

- 프론트엔드: `http://localhost:5174/login`
- 백엔드 API: `http://localhost:8000/api/v1`

로그인 화면에서 관리자 계정으로 로그인합니다.

로그인 후 기본적으로 관리자 레이아웃이 표시되며, 좌측 메뉴에서 구축 워크플로우, 관리 기능, 운영/분석, 시스템 관리 기능을 사용할 수 있습니다.

### 3.2 프로젝트 선택 기준

J-Brain은 프로젝트 단위로 Source, Intent, FAQ, Action, Pack을 관리합니다.

현재 J-Brain 챗봇 구축 테스트는 `J-Brain` 프로젝트를 기준으로 수행합니다.

운영자가 프로젝트를 바꾸면 다음 데이터 범위가 함께 바뀝니다.

- Source 목록
- Intent 목록
- Entity/Synonym 목록
- FAQ 목록
- Action 목록
- Pack Draft/Export/Runtime Pack 이력
- 검증 질문 및 검증 결과
- Runtime QA 대상 Pack

## 5. J-Brain 챗봇 구축 표준 절차

### 5.1 1단계: 기반 설정

기반 설정은 프로젝트 작업을 시작하기 위한 기준 정보를 고정하는 단계입니다.

확인 항목은 다음과 같습니다.

- 프로젝트 ID
- 프로젝트명
- 프로젝트 상태
- 설명
- 최근 등록 문서 수
- 현재 구축 단계

운영 절차는 다음과 같습니다.

1. 좌측 메뉴에서 `구축 워크플로우 > 프로젝트 선택/목록`을 선택합니다.
2. `J-Brain` 프로젝트를 선택합니다.
3. `1. 기반 설정` 단계로 이동합니다.
4. 프로젝트 기본 정보가 J-Brain 챗봇 테스트 목적과 맞는지 확인합니다.
5. 변경이 필요한 경우 `프로젝트 관리` 화면으로 이동하여 수정합니다.

완료 기준은 다음과 같습니다.

- 프로젝트가 목록에 표시됩니다.
- 프로젝트 상태가 활성 또는 테스트 가능한 상태입니다.
- 이후 단계에서 사용할 프로젝트가 `J-Brain`으로 선택됩니다.

### 5.2 2단계: 지식 준비

지식 준비는 챗봇이 답변할 수 있는 Source 문서를 등록하고 검색 가능한 상태로 만드는 단계입니다.

운영 절차는 다음과 같습니다.

1. `Source 관리` 화면으로 이동합니다.
2. `J-Brain_Manual.txt` 또는 운영 문서를 Source로 등록합니다.
3. 벡터화 작업을 실행합니다.
4. `벡터화 작업 현황`에서 작업 상태를 확인합니다.
5. `검색 테스트`에서 대표 질문을 입력해 문서 검색 결과를 확인합니다.

대표 검색 질문은 다음과 같습니다.

- J-Brain은 무엇인가요?
- Source 관리는 어떤 기능인가요?
- Intent Factory는 어떤 순서로 사용하나요?
- Pack Build는 언제 수행하나요?
- Runtime QA에서는 무엇을 확인하나요?

완료 기준은 다음과 같습니다.

- Source가 1건 이상 등록되어 있습니다.
- 벡터화 작업이 성공 상태입니다.
- 검색 테스트에서 J-Brain 문서 근거가 반환됩니다.

### 5.3 3단계: 의도 설계

의도 설계는 사용자의 질문 목적을 Intent로 정의하는 단계입니다.

J-Brain 챗봇의 대표 Intent 예시는 다음과 같습니다.

| Intent 예시 | 목적 | 권장 Action |
| --- | --- | --- |
| J-Brain 소개 안내 | J-Brain 개념 설명 | SEARCH_DOC 또는 GUIDE |
| Source 관리 안내 | Source 등록/검색/벡터화 설명 | SEARCH_DOC |
| Intent Factory 사용 안내 | Intent 설계 절차 설명 | SEARCH_DOC 또는 GUIDE |
| Pack Build 안내 | Pack 생성과 Export 설명 | SEARCH_DOC 또는 NAVIGATE |
| Runtime QA 안내 | Runtime 테스트 방법 설명 | SEARCH_DOC 또는 NAVIGATE |
| 메뉴 이동 | 운영자가 특정 관리 화면으로 이동 | NAVIGATE |

운영 절차는 다음과 같습니다.

1. `Intent 관리` 화면으로 이동합니다.
2. 프로젝트를 `J-Brain`으로 선택합니다.
3. `Intent 등록`을 클릭합니다.
4. Intent ID, Intent 이름, Category, Action ID, 설명을 입력합니다.
5. 예시 질문을 3개 이상 등록합니다.
6. 필요한 경우 Source 검색 범위를 지정합니다.
7. 저장 후 목록에서 상태를 확인합니다.

완료 기준은 다음과 같습니다.

- 대표 Intent가 등록되어 있습니다.
- 각 Intent에 예시 질문이 포함되어 있습니다.
- Intent와 Action ID가 연결되어 있습니다.

### 5.4 4단계: 질문 커버리지

질문 커버리지는 실제 사용자가 다르게 표현하는 질문을 Intent Example로 보강하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `Intent 관리`에서 Intent 상세 화면으로 이동합니다.
2. 예시 질문 목록을 확인합니다.
3. 실제 사용자가 입력할 표현을 추가합니다.
4. 중복되거나 모호한 질문은 정리합니다.

예시는 다음과 같습니다.

| Intent | 예시 질문 |
| --- | --- |
| J-Brain 소개 안내 | J-Brain이 뭔가요? / J-Brain은 어떤 시스템인가요? / 이 시스템의 핵심 기능을 알려줘 |
| Source 관리 안내 | 문서는 어디서 등록하나요? / Source 등록 방법 알려줘 / 벡터화는 어디서 확인해? |
| Pack Build 안내 | Pack은 어떻게 만들어요? / ZIP Export는 어디서 하나요? / 고객망에 반입할 파일은 어떻게 생성해? |

완료 기준은 다음과 같습니다.

- 주요 Intent별 예시 질문이 충분히 등록되어 있습니다.
- 같은 질문이 여러 Intent에 중복되지 않습니다.
- Runtime QA에서 Top-1 또는 Top-3 내 기대 Intent가 반환됩니다.

### 5.5 5단계: 용어 사전

용어 사전은 같은 의미의 표현을 Entity와 Synonym으로 정리하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `Entity/Synonym 관리` 화면으로 이동합니다.
2. Entity 유형을 등록합니다.
3. Synonym 목록에 동의어, 약어, 영문 표현을 등록합니다.
4. 필요한 경우 Intent 상세 화면에서 Entity 후보를 연결합니다.

J-Brain 권장 Entity 예시는 다음과 같습니다.

| Entity | Synonym 예시 |
| --- | --- |
| SOURCE | Source, 지식문서, 문서, 자료 |
| INTENT | Intent, 의도, 질문 의도 |
| PACK | Pack, Intent Pack, 배포 패키지, ZIP |
| RUNTIME | Runtime, 챗봇 엔진, 고객망 엔진 |
| FAQ | FAQ, 자주 묻는 질문, 문답 |

완료 기준은 다음과 같습니다.

- 주요 운영 용어가 Entity로 등록되어 있습니다.
- 사용자가 자주 쓰는 표현이 Synonym으로 등록되어 있습니다.
- Intent 매칭 결과에 Entity 보너스가 반영될 수 있습니다.

### 5.6 6단계: 답변 근거

답변 근거는 FAQ와 Source 문서가 Runtime 응답의 근거로 사용될 수 있도록 정리하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `FAQ 관리` 화면으로 이동합니다.
2. FAQ ID, 질문, 답변, 분류, 태그를 입력합니다.
3. 필요 시 Source ID를 연결합니다.
4. `Pack Export에 반영` 옵션을 켭니다.
5. 저장 후 FAQ 목록에서 Pack 반영 여부를 확인합니다.

FAQ 등록 예시는 다음과 같습니다.

| FAQ ID | 질문 | 답변 요약 |
| --- | --- | --- |
| FAQ-JB-001 | J-Brain은 무엇인가요? | J-Brain은 프로젝트별 지식 문서와 Intent Pack을 관리하는 챗봇 운영 플랫폼입니다. |
| FAQ-JB-002 | Source 관리는 무엇인가요? | Source 관리는 챗봇 답변 근거가 되는 문서를 등록하고 벡터화 상태를 확인하는 기능입니다. |
| FAQ-JB-003 | Pack은 왜 필요한가요? | Pack은 고객 내부망 Runtime에 반입할 Intent, Action, FAQ, 설정 파일의 배포 단위입니다. |

완료 기준은 다음과 같습니다.

- FAQ가 등록되어 있습니다.
- Pack 반영 대상 FAQ가 선택되어 있습니다.
- Pack Export 후 `knowledge/faqs.json`에 FAQ가 포함됩니다.
- Runtime QA에서 FAQ 기반 근거가 표시됩니다.

### 5.7 7단계: 실행 연결

실행 연결은 Intent가 실제 Action으로 이어지는지 확인하는 단계입니다.

Action 유형은 다음과 같습니다.

| Action 유형 | 설명 | 예시 |
| --- | --- | --- |
| NAVIGATE | 지정 화면으로 이동하는 버튼을 반환합니다. | Source 관리 화면 이동 |
| SEARCH_DOC | FAQ와 Source 문서를 검색합니다. | J-Brain 사용법 검색 |
| QUERY | 정형 데이터 조회를 수행합니다. | 통계 조회 |
| GUIDE | 정해진 안내 문구나 절차를 반환합니다. | Pack Build 절차 안내 |
| CREATE_REQUEST | 개선 요청 또는 미응답 후보를 생성합니다. | FAQ 후보 등록 |

운영 절차는 다음과 같습니다.

1. `Action 관리` 화면으로 이동합니다.
2. Action ID, Action 이름, 유형, 설명을 등록합니다.
3. NAVIGATE 유형은 메뉴명과 Route 값을 입력합니다.
4. Intent 상세 화면에서 Action ID를 연결합니다.
5. Runtime QA 또는 Action 실행 테스트에서 결과를 확인합니다.

완료 기준은 다음과 같습니다.

- 미연결 Intent가 없습니다.
- Action ID가 실제 Action 목록에 존재합니다.
- NAVIGATE Action은 실제 화면 경로와 연결됩니다.
- SEARCH_DOC Action은 FAQ와 Source 검색 범위를 사용할 수 있습니다.

### 5.8 8단계: Pack 품질검증

Pack 품질검증은 검증 질문을 기준으로 Pack이 기대 Intent/Action을 반환하는지 확인하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `Pack 검증` 화면으로 이동합니다.
2. 프로젝트를 `J-Brain`으로 선택합니다.
3. 검증 질문을 등록합니다.
4. 기대 Intent ID, 기대 Action ID, 최소 Confidence 기준을 입력합니다.
5. 검증 대상 Pack을 선택합니다.
6. `검증 실행`을 클릭합니다.
7. Pass/Fail 결과와 실패 원인을 확인합니다.

검증 질문 예시는 다음과 같습니다.

| 질문 | 기대 Intent | 기대 Action |
| --- | --- | --- |
| J-Brain은 무엇인가요? | INT-JB-DOC-INTRO | ACT-JB-SEARCH-DOC |
| Source 등록 방법 알려줘 | INT-JB-DOC-SOURCE | ACT-JB-SEARCH-DOC |
| Pack Builder 화면으로 이동해줘 | INT-JB-NAV-PACK-BUILDER | ACT-JB-GO-PACK-BUILDER |
| Runtime QA는 어디서 하나요? | INT-JB-DOC-RUNTIME-QA | ACT-JB-SEARCH-DOC |

완료 기준은 다음과 같습니다.

- 필수 검증 질문이 등록되어 있습니다.
- 검증 실행 결과가 저장됩니다.
- 실패 항목은 Intent Example, FAQ, Action 연결 중 어느 부분을 고쳐야 하는지 확인됩니다.

### 5.9 9단계: Runtime 시뮬레이션

Runtime 시뮬레이션은 사용자가 실제로 질문했을 때 어떤 응답과 Action Card가 반환되는지 확인하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `챗봇 대화 테스트` 화면으로 이동합니다.
2. 프로젝트를 `J-Brain`으로 선택합니다.
3. Pack 모드를 선택합니다.
   - 기본 파일 Pack
   - Active Pack
   - DB Draft Pack 확인
4. 대표 질문을 입력합니다.
5. 답변, Top-3 Intent 후보, Action Card, FAQ/Source 근거를 확인합니다.

확인 질문 예시는 다음과 같습니다.

- J-Brain은 무엇인가요?
- Source 관리는 어떻게 하나요?
- Intent Factory는 어떤 순서로 사용하나요?
- Pack Export는 어디서 하나요?
- Runtime QA 화면으로 이동해줘

완료 기준은 다음과 같습니다.

- 기대 Intent가 Top-1 또는 Top-3에 포함됩니다.
- 응답 근거가 표시됩니다.
- Action Card가 의도한 유형으로 반환됩니다.
- 낮은 신뢰도 질문은 미응답 분석 대상으로 기록됩니다.

### 5.10 10단계: Pack Build

Pack Build는 DB에 저장된 Intent, Entity, FAQ, Action 정보를 표준 Intent Pack 구조로 Export하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `Pack Builder` 화면으로 이동합니다.
2. 프로젝트를 `J-Brain`으로 선택합니다.
3. `Draft 생성`을 클릭합니다.
4. Intent, Example, Entity, FAQ, Action 건수를 확인합니다.
5. `Export / ZIP 생성`을 클릭합니다.
6. 검증 상태와 Export ID를 확인합니다.
7. 필요하면 ZIP 파일을 다운로드합니다.

Pack ZIP에는 다음 파일이 포함됩니다.

- `manifest/pack_manifest.json`
- `profile/service_profile.json`
- `nlu/intents.json`
- `nlu/intent_examples.json`
- `nlu/entities.json`
- `action/action_registry.json`
- `action/screen_routes.json`
- `knowledge/faqs.json`
- `knowledge/approved_documents.json`
- `templates/response_templates.json`
- `validation/validation_questions.json`

완료 기준은 다음과 같습니다.

- Export 결과가 생성됩니다.
- Validation 결과가 통과 상태입니다.
- ZIP 다운로드가 가능합니다.
- Pack Repository에 Export 이력이 표시됩니다.

### 5.11 11단계: 배포/활성화

배포/활성화는 Export된 Pack ZIP을 Runtime Pack Store에 반입하고 운영 대상 Pack으로 전환하는 단계입니다.

운영 절차는 다음과 같습니다.

1. `Pack Repository` 화면으로 이동합니다.
2. Export ZIP 이력에서 대상 Pack을 확인합니다.
3. `Import`를 실행합니다.
4. Runtime Pack Store에 Pack이 등록되었는지 확인합니다.
5. 검증 상태가 `validated`인지 확인합니다.
6. `Approve`를 클릭해 승인합니다.
7. `Activate`를 클릭해 Active Pack으로 전환합니다.
8. 문제가 있으면 Rollback 후보 Pack으로 되돌립니다.

운영 정책은 다음과 같습니다.

- 승인되지 않은 Pack은 Active 전환할 수 없습니다.
- Active Pack 전환 전 이전 정상 Pack이 Rollback 후보로 보관됩니다.
- Import, Approve, Reject, Activate, Rollback 이벤트는 감사 로그에 남습니다.

완료 기준은 다음과 같습니다.

- Runtime Pack Store에 Pack이 존재합니다.
- Pack이 승인 상태입니다.
- Active Pack이 지정되어 있습니다.
- Runtime QA에서 Active Pack 선택이 가능합니다.

### 5.12 12단계: 운영 분석/개선

운영 분석/개선은 배포 후 실제 사용 질문을 바탕으로 다음 Pack 개선 후보를 만드는 단계입니다.

운영 절차는 다음과 같습니다.

1. `미응답 분석` 화면으로 이동합니다.
2. 낮은 신뢰도 질문, 검색 실패 질문, 미지원 Action 질문을 확인합니다.
3. 질문을 FAQ 후보, Intent 개선 후보, Source 보강 후보로 분류합니다.
4. `개선 요청 관리`에서 우선순위와 상태를 관리합니다.
5. 다음 Draft Pack에 반영할 항목을 정리합니다.
6. `Pack 개선 이력`에서 반영 내역을 추적합니다.

완료 기준은 다음과 같습니다.

- 미응답 질문이 분류되어 있습니다.
- 개선 요청 상태가 관리됩니다.
- 다음 Pack에 반영할 후보가 정리됩니다.

## 6. Runtime QA 사용 방법

Runtime QA는 J-Brain 챗봇을 운영 전 검증하는 핵심 화면입니다.

### 6.1 테스트 전 확인 사항

- Source가 등록되어 있습니다.
- Intent가 등록되어 있습니다.
- FAQ 또는 Source 검색 근거가 준비되어 있습니다.
- Action이 등록되어 있습니다.
- Pack이 Export 또는 Active 상태입니다.

### 6.2 테스트 방법

1. `운영/분석 > 챗봇 대화 테스트`로 이동합니다.
2. 프로젝트를 `J-Brain`으로 선택합니다.
3. Pack 선택 옵션을 확인합니다.
4. 질문을 입력하고 전송합니다.
5. 응답 결과를 확인합니다.

### 6.3 확인해야 할 결과

- Top Intent ID
- Intent 이름
- Confidence Label
- Action ID
- Action Card 유형
- FAQ 검색 결과
- Source 검색 근거
- Top-3 Intent 후보

### 6.4 실패 시 조치

| 증상 | 확인 위치 | 조치 |
| --- | --- | --- |
| Intent가 맞지 않음 | Intent 관리 | Example 추가 또는 중복 Intent 정리 |
| Confidence가 낮음 | Intent 상세, Entity 관리 | Synonym 추가, 질문 표현 보강 |
| 답변 근거가 없음 | Source 관리, FAQ 관리 | Source 등록, FAQ 승인, Source Scope 확인 |
| Action Card가 없음 | Action 관리 | Action ID 등록 및 Intent 연결 확인 |
| Active Pack이 없음 | Pack Repository | Import, Approve, Activate 순서 확인 |

## 7. J-Brain 초기 구축 테스트 시나리오

J-Brain 챗봇을 처음부터 테스트할 때는 다음 순서로 진행합니다.

1. `J-Brain_Manual.txt`를 Source로 등록합니다.
2. 벡터화 작업을 실행합니다.
3. 검색 테스트에서 “J-Brain은 무엇인가요?”를 입력합니다.
4. Intent 관리에서 J-Brain 대표 Intent를 등록합니다.
5. Entity/Synonym 관리에서 J-Brain 운영 용어를 등록합니다.
6. FAQ 관리에서 J-Brain FAQ를 등록합니다.
7. Action 관리에서 SEARCH_DOC, NAVIGATE, GUIDE Action을 등록합니다.
8. Intent 상세에서 Action과 Entity를 연결합니다.
9. Pack Builder에서 Draft를 생성합니다.
10. Pack Export ZIP을 생성합니다.
11. Pack Repository에서 Import합니다.
12. Pack 검증 질문을 등록하고 실행합니다.
13. 검증 통과 Pack을 승인합니다.
14. 승인된 Pack을 Active 전환합니다.
15. Runtime QA에서 대표 질문을 실행합니다.
16. 미응답 분석에서 낮은 신뢰도 질문을 확인합니다.
17. 개선 후보를 FAQ 또는 Intent 보강 항목으로 등록합니다.

## 8. J-Brain 대표 질문 세트

초기 테스트에 사용할 대표 질문은 다음과 같습니다.

### 8.1 설명형 질문

- J-Brain은 무엇인가요?
- J-Brain의 핵심 기능은 무엇인가요?
- Intent Factory는 어떤 기능인가요?
- Source 관리는 어떤 작업을 하나요?
- Pack은 왜 필요한가요?
- Runtime QA는 무엇을 확인하는 화면인가요?

### 8.2 절차형 질문

- J-Brain 챗봇 구축 순서를 알려줘
- Source 문서는 어떻게 등록하나요?
- 벡터화 작업은 어디서 확인하나요?
- Intent는 어떻게 등록하나요?
- FAQ는 Pack에 어떻게 반영되나요?
- Pack Export는 어떻게 하나요?
- Active Pack 전환은 어떤 순서로 하나요?

### 8.3 화면 이동형 질문

- Source 관리 화면으로 이동해줘
- Intent 관리 열어줘
- Pack Builder 화면으로 가줘
- Runtime QA 화면 보여줘
- 미응답 분석 화면으로 이동해줘

### 8.4 개선형 질문

- 이 질문은 왜 답을 못 하나요?
- FAQ 후보로 등록해줘
- 이 답변을 개선 요청으로 남겨줘
- 다음 Pack에 반영할 개선 항목을 보여줘

## 9. 폐쇄망 운영 원칙

J-Brain의 Intent Factory 구조는 외부망과 고객 내부망을 분리하는 것을 전제로 합니다.

### 9.1 외부망 역할

외부망에서는 다음 작업을 수행합니다.

- Source 분석
- Intent 후보 정리
- FAQ 후보 정리
- Pack Draft 생성
- 전문가 검수
- Pack Export ZIP 생성
- 배포 패키지 버전 관리

### 9.2 고객 내부망 역할

고객 내부망에서는 다음 작업을 수행합니다.

- Pack Import
- Pack Loader 검증
- Runtime Pack Store 저장
- Active Pack 전환
- Runtime QA
- 챗봇 서비스 운영
- 운영 로그 및 미응답 수집

### 9.3 보안 원칙

- 고객 원문 데이터는 고객 내부망 또는 승인된 저장소에서만 관리합니다.
- 외부 LLM/API 호출은 Runtime 운영 경로에서 사용하지 않습니다.
- Runtime은 검증된 Pack 파일을 기준으로 동작합니다.
- Action은 Whitelist에 등록된 항목만 실행합니다.
- Pack Import, 승인, 활성화, Rollback은 감사 로그로 남깁니다.

## 10. 주요 화면별 운영 요약

### 10.1 프로젝트 관리

프로젝트 관리 화면은 프로젝트 기본 정보와 상태를 확인하는 화면입니다.

운영자는 프로젝트명, 설명, 상태를 확인하고 Source/Intent/Pack 관리의 기준 프로젝트를 선택합니다.

### 10.2 Source 관리

Source 관리 화면은 챗봇 답변 근거가 되는 문서를 등록하는 화면입니다.

등록 후 벡터화 작업을 실행해야 Runtime 검색에서 사용할 수 있습니다.

### 10.3 벡터화 작업 현황

벡터화 작업 현황 화면은 Source 문서가 검색 가능한 상태로 처리되었는지 확인하는 화면입니다.

작업 실패 시 오류 메시지를 확인하고 Source 파일 형식, 텍스트 추출 가능 여부, DB 연결 상태를 점검합니다.

### 10.4 검색 테스트

검색 테스트 화면은 Source 문서와 FAQ가 실제 질문에 대해 검색되는지 확인하는 화면입니다.

Intent 설계 전에는 문서 근거 품질을 확인하는 용도로 사용하고, Pack 검증 전에는 FAQ/Source 반영 여부를 확인하는 용도로 사용합니다.

### 10.5 Intent 관리

Intent 관리 화면은 질문 의도와 실행 Action을 연결하는 화면입니다.

Intent는 질문 분류의 최소 단위이며, Example은 사용자가 실제로 입력할 수 있는 표현입니다.

### 10.6 Entity/Synonym 관리

Entity/Synonym 관리 화면은 업무 용어와 동의어를 정리하는 화면입니다.

예를 들어 “문서”, “Source”, “지식문서”를 같은 의미로 인식하도록 Synonym을 등록할 수 있습니다.

### 10.7 FAQ 관리

FAQ 관리 화면은 자주 묻는 질문과 승인된 답변을 등록하는 화면입니다.

FAQ는 Pack Export 시 `knowledge/faqs.json`에 포함되며, Runtime의 SEARCH_DOC Action에서 검색 대상이 됩니다.

### 10.8 Action 관리

Action 관리 화면은 Intent가 실행할 업무 동작을 정의하는 화면입니다.

현재 주요 유형은 NAVIGATE, SEARCH_DOC, QUERY, GUIDE, CREATE_REQUEST입니다.

### 10.9 Pack Builder

Pack Builder 화면은 DB에 저장된 Intent, Entity, FAQ, Action 정보를 표준 Pack 구조로 변환합니다.

Export가 완료되면 ZIP 다운로드와 Repository 이력 확인이 가능합니다.

### 10.10 Pack 검증

Pack 검증 화면은 검증 질문을 등록하고 기대 Intent/Action과 실제 결과를 비교하는 화면입니다.

검증 실패 항목은 Runtime 배포 전 반드시 보완해야 합니다.

### 10.11 Pack Repository

Pack Repository 화면은 Export ZIP, Runtime Pack Store, Active Pack, Rollback 후보를 관리합니다.

운영 Pack 전환은 Import, Approve, Activate 순서로 진행합니다.

### 10.12 Runtime QA

Runtime QA 화면은 실제 사용자 질문을 입력해 Runtime 응답을 확인하는 화면입니다.

답변, Action Card, Intent 진단, FAQ/Source 근거를 함께 확인합니다.

### 10.13 미응답 분석

미응답 분석 화면은 낮은 신뢰도 질문과 답변 실패 질문을 확인하는 화면입니다.

분석 결과는 FAQ 후보, Intent 보강, Source 보강, Action 추가 요청으로 전환할 수 있습니다.

## 11. 장애 및 점검 가이드

### 11.1 로그인 실패

확인 항목은 다음과 같습니다.

- 백엔드 서버 실행 여부
- `/api/v1/auth/login/mock` 응답 상태
- 브라우저 콘솔의 500 오류
- 백엔드 로그의 Python 버전 호환성 오류

Python 3.9 환경에서는 `Path | str` 같은 3.10 이상 문법이 오류를 일으킬 수 있으므로, 타입 힌트 호환성을 확인합니다.

### 11.2 프로젝트 목록이 비어 있음

확인 항목은 다음과 같습니다.

- 백엔드 `/api/v1/workflow/projects` 응답 여부
- `graphrag.graphrag_sources`에 프로젝트 category 데이터 존재 여부
- 네트워크 탭의 404 또는 500 오류

### 11.3 Source 검색 결과가 없음

확인 항목은 다음과 같습니다.

- Source 등록 여부
- 벡터화 작업 성공 여부
- Chunk 생성 여부
- 검색어가 문서 내용과 관련 있는지 여부
- 프로젝트 선택이 올바른지 여부

### 11.4 Intent 매칭이 부정확함

확인 항목은 다음과 같습니다.

- Intent Example 수
- 중복 Intent 여부
- Entity/Synonym 등록 여부
- Confidence Policy 기준
- 질문이 해당 프로젝트 범위에 맞는지 여부

### 11.5 Pack Export 실패

확인 항목은 다음과 같습니다.

- Intent 존재 여부
- Action ID 연결 여부
- 필수 Pack 파일 생성 여부
- Validation 오류 메시지
- Export 저장 경로 권한

### 11.6 Active Pack 전환 실패

확인 항목은 다음과 같습니다.

- Runtime Pack이 Import 되었는지 여부
- Pack 상태가 `approved`인지 여부
- 이전 검증 결과가 통과했는지 여부
- Pack Loader 검증 오류 여부

J-Brain 챗봇을 운영 반영하기 전에 다음 항목을 확인합니다.

| Intent | 대표 Intent 등록 | Intent 5건 이상 권장 |
| Example | 질문 표현 등록 | Intent별 3건 이상 권장 |

| Import | Runtime Store 반입 | Import 성공 |
| 승인 | Pack 승인 | Approved 상태 |
| 활성화 | Active Pack 전환 | Runtime QA에서 선택 가능 |
| 운영 | 미응답 분석 | 개선 후보 분류 가능 |

## 13. 현재 구현 상태 기준 주의사항

현재 시스템은 실제 운영 구조를 목표로 개발 중인 상태이며, 일부 화면은 v0.1 진입점 또는 관리 쉘 형태입니다.

주의할 화면은 다음과 같습니다.

- `LLM 지원 도구`: 외부망 후보 생성 지원 도구의 진입점입니다. Runtime 운영 경로와는 분리됩니다.
- `Action 실행 테스트`: 현재는 Action 테스트 진입점이며, 상세 실행 화면은 Runtime QA와 Intent 매칭 테스트 결과를 함께 확인합니다.
- `고객 위젯 미리보기`: 위젯 적용 전 미리보기 화면입니다. 실제 고객 사이트 삽입 스크립트는 별도 배포 단계에서 확정합니다.
- `시스템 설정`: 공통 설정 관리 진입점입니다. 세부 운영 설정은 추후 단계에서 확장됩니다.

운영자는 실제 Pack 반영 여부를 확인할 때 반드시 다음 순서를 사용해야 합니다.

1. DB 관리 화면에서 데이터 저장
2. Pack Builder에서 Draft 생성
3. Export ZIP 생성
4. Pack Repository에서 Import
5. Pack 검증
6. Pack 승인
7. Active 전환
8. Runtime QA 확인

DB에 데이터를 저장했다고 해서 Runtime이 즉시 DB를 직접 읽는 것은 아닙니다. Runtime은 검증된 파일 Pack 또는 Active Pack을 기준으로 동작합니다.

## 16. 문서 관리

이 문서는 J-Brain Source로 등록하여 챗봇이 J-Brain 운영 방법을 답변할 수 있도록 사용하는 기준 문서입니다.

문서를 수정한 후에는 다음 작업을 수행합니다.

1. Source 관리에서 기존 J-Brain 매뉴얼 Source를 교체하거나 신규 등록합니다.
2. 벡터화 작업을 다시 실행합니다.
3. 검색 테스트에서 대표 질문을 확인합니다.
4. FAQ와 Intent가 변경된 내용과 충돌하지 않는지 확인합니다.
5. 필요한 경우 Pack Build와 Runtime QA를 다시 수행합니다.

문서 버전은 다음 기준으로 관리합니다.

- v3.0: 구축 워크플로우, Intent Factory, Pack 운영, Runtime QA 기준 반영
- 향후 버전: 고객 위젯, Action 실행 테스트 상세화, 운영 리포트, 승인 워크플로우 고도화 반영 예정

## 17. 운영자 응대용 표준 답변

이 장은 J-Brain 운영자가 사용자 질문에 직접 답변하거나, 챗봇 FAQ/Intent 답변 근거로 사용할 수 있도록 구성한 표준 응대 문구입니다.

답변 시 기본 원칙은 다음과 같습니다.

- 먼저 사용자의 질문 의도를 짧게 확인합니다.
- 가능한 경우 화면 경로를 함께 안내합니다.
- 작업 순서가 필요한 질문은 번호 목록으로 설명합니다.
- 시스템 상태나 데이터가 필요한 질문은 실제 화면에서 확인하도록 안내합니다.
- 확정되지 않은 기능은 현재 구현 상태와 향후 확장 예정 범위를 구분해서 설명합니다.

### 17.1 J-Brain 개요 관련 질문

#### Q. J-Brain은 무엇인가요?

J-Brain은 프로젝트별 지식 문서, Intent, FAQ, Action, Pack을 관리하여 폐쇄망 환경에서도 챗봇을 운영할 수 있게 하는 AI 챗봇 구축/운영 플랫폼입니다.

운영자는 J-Brain에서 Source 문서를 등록하고, 사용자의 질문 의도를 Intent로 정의한 뒤, 검증된 Intent Pack을 생성하여 Runtime 챗봇에 반영할 수 있습니다.

#### Q. J-Brain의 핵심 기능은 무엇인가요?

J-Brain의 핵심 기능은 다음과 같습니다.

1. 프로젝트별 지식 문서 관리
2. Source 문서 벡터화 및 검색 테스트
3. Intent, Example, Entity, Synonym 관리
4. FAQ 및 답변 근거 관리
5. Action 연결 관리
6. Pack Build, Export, Import, 승인, 활성화
7. Runtime QA와 미응답 분석
8. 운영 개선 후보 관리

#### Q. J-Brain은 일반 LLM 챗봇과 무엇이 다른가요?

J-Brain은 Runtime 운영 시 외부 LLM/API 호출에 의존하지 않는 구조를 목표로 합니다.

외부망에서는 Intent Pack을 만들고 검증하며, 고객 내부망 Runtime에는 검증된 Pack만 반입합니다. Runtime은 Pack에 포함된 Intent, FAQ, Action, 설정을 기준으로 질문을 매칭하고 허용된 Action만 실행합니다.

#### Q. J-Brain은 고객 내부망에서도 사용할 수 있나요?

네. J-Brain의 목표 구조는 고객 내부망에서 Runtime 챗봇 엔진과 Pack Store를 운영하는 것입니다.

고객 내부망에는 고객 데이터와 Runtime Pack이 존재하고, 외부망과는 Pack 배포, 운영 요청, 피드백 정도만 교환하는 구조를 권장합니다.

### 17.2 구축 절차 관련 질문

#### Q. J-Brain 챗봇은 어떤 순서로 구축하나요?

J-Brain 챗봇은 다음 12단계 흐름으로 구축합니다.

1. 기반 설정
2. 지식 준비
3. 의도 설계
4. 질문 커버리지
5. 용어 사전
6. 답변 근거
7. 실행 연결
8. Pack 품질검증
9. Runtime 시뮬레이션
10. Pack Build
11. 배포/활성화
12. 운영 분석/개선

화면에서는 `구축 워크플로우 > 워크플로우 대시보드`에서 현재 단계와 다음 작업을 확인할 수 있습니다.

#### Q. 처음 구축 테스트를 하려면 어디서 시작해야 하나요?

처음 구축 테스트는 `구축 워크플로우 > 프로젝트 선택/목록`에서 프로젝트를 선택하는 것부터 시작합니다.

J-Brain 테스트의 경우 `J-Brain` 프로젝트를 선택한 뒤, `1. 기반 설정`부터 단계별로 진행하면 됩니다.

#### Q. 워크플로우 대시보드는 어떤 화면인가요?

워크플로우 대시보드는 프로젝트 구축 상태를 한눈에 확인하는 화면입니다.

운영자는 이 화면에서 현재 진행 단계, 완료 조건, 미완료 항목, 다음 작업, 주요 이동 버튼을 확인할 수 있습니다.

#### Q. 각 단계별 화면으로 이동하려면 어떻게 하나요?

좌측 메뉴의 `구축 워크플로우` 아래에 있는 단계 메뉴를 클릭하거나, 워크플로우 대시보드의 단계 카드와 주요 화면 이동 버튼을 사용합니다.

프로젝트가 선택된 상태라면 `/admin/workflow/projects/{projectId}/stages/{stageNo}` 경로로 각 단계 화면에 접근할 수 있습니다.

### 17.3 Source 및 지식 준비 관련 질문

#### Q. Source는 무엇인가요?

Source는 챗봇이 답변 근거로 사용할 원천 문서입니다.

예를 들어 운영 매뉴얼, 업무 가이드, FAQ 원문, 정책 문서, 고객 시스템 사용 설명서 등이 Source가 될 수 있습니다.

#### Q. Source와 FAQ는 무엇이 다른가요?

Source는 원문 문서입니다. 문서 전체를 벡터화하여 검색 근거로 사용합니다.

FAQ는 운영자가 승인한 질문과 답변 쌍입니다. 사용자가 자주 묻는 질문에 대해 더 직접적이고 짧은 답변을 제공할 때 사용합니다.

SEARCH_DOC Action은 FAQ와 Source 문서를 함께 검색 대상으로 사용할 수 있습니다.

#### Q. 문서를 등록하면 바로 챗봇이 답변할 수 있나요?

아닙니다. 문서를 등록한 뒤에는 벡터화 작업이 완료되어야 검색 근거로 사용할 수 있습니다.

확인 순서는 다음과 같습니다.

1. `Source 관리`에서 문서 등록
2. `벡터화 작업 현황`에서 작업 성공 확인
3. `검색 테스트`에서 대표 질문 검색
4. 필요 시 FAQ 또는 Intent에 반영
5. Pack Build 및 Runtime QA 수행

#### Q. 벡터화 작업은 어디서 확인하나요?

`관리 기능 > 벡터화 작업 현황` 또는 `/admin/knowledge/jobs` 화면에서 확인합니다.

작업 상태가 성공이면 검색 테스트를 진행할 수 있고, 실패이면 오류 메시지와 Source 파일 상태를 확인해야 합니다.

#### Q. 검색 테스트는 왜 필요한가요?

검색 테스트는 챗봇 답변의 근거가 되는 문서가 실제 질문에 잘 검색되는지 확인하는 단계입니다.

검색 테스트에서 원하는 문서가 나오지 않으면, Source 내용이 부족하거나 질문 표현과 문서 표현이 맞지 않을 수 있습니다. 이 경우 Source 보강, FAQ 등록, Synonym 추가를 검토합니다.

### 17.4 Intent 관련 질문

#### Q. Intent는 무엇인가요?

Intent는 사용자가 질문한 목적 또는 의도를 의미합니다.

예를 들어 “Source 등록 방법 알려줘”라는 질문은 `Source 관리 안내` Intent로 분류할 수 있고, “Pack Builder 화면으로 이동해줘”는 `Pack Builder 화면 이동` Intent로 분류할 수 있습니다.

#### Q. Intent Example은 무엇인가요?

Intent Example은 특정 Intent에 매칭될 수 있는 예시 질문입니다.

사용자는 같은 의도를 여러 표현으로 질문하기 때문에, 운영자는 다양한 표현을 Example로 등록해야 합니다.

예시는 다음과 같습니다.

- Source 등록 방법 알려줘
- 문서는 어디서 올려?
- 지식 문서 추가하는 화면 열어줘
- 매뉴얼 파일은 어떻게 등록하나요?

#### Q. Intent는 몇 개 정도 등록해야 하나요?

초기 테스트 단계에서는 핵심 업무 흐름을 기준으로 5~10개 정도의 대표 Intent부터 등록하는 것이 좋습니다.

운영 단계에서는 미응답 분석 결과를 보면서 필요한 Intent를 점진적으로 늘립니다.

#### Q. Intent와 FAQ는 어떻게 구분하나요?

Intent는 질문을 어떤 업무 동작으로 보낼지 결정하는 분류 기준입니다.

FAQ는 특정 질문에 대해 바로 제공할 수 있는 승인된 답변입니다.

예를 들어 “Pack은 왜 필요한가요?”는 FAQ 답변으로 처리할 수 있고, “Pack Builder 화면으로 이동해줘”는 NAVIGATE Action과 연결된 Intent로 처리하는 것이 적절합니다.

#### Q. Intent 매칭이 잘 안 되면 어떻게 해야 하나요?

다음 순서로 확인합니다.

1. Intent Example이 충분한지 확인합니다.
2. 비슷한 Intent가 중복되어 있는지 확인합니다.
3. Entity/Synonym이 등록되어 있는지 확인합니다.
4. 질문 표현이 Source/FAQ의 용어와 지나치게 다른지 확인합니다.
5. Runtime QA의 Top-3 후보와 Confidence Label을 확인합니다.

### 17.5 Entity/Synonym 관련 질문

#### Q. Entity는 무엇인가요?

Entity는 질문 안에서 의미 있는 업무 개체나 용어를 말합니다.

예를 들어 J-Brain에서는 `Source`, `Intent`, `Pack`, `Runtime`, `FAQ`, `Action` 같은 용어가 Entity가 될 수 있습니다.

#### Q. Synonym은 무엇인가요?

Synonym은 같은 의미로 처리할 표현입니다.

예를 들어 `Source`의 Synonym으로 “문서”, “지식문서”, “자료”, “원천 문서”를 등록하면 사용자가 어떤 표현을 쓰더라도 더 안정적으로 매칭할 수 있습니다.

#### Q. Entity/Synonym은 꼭 등록해야 하나요?

초기 테스트에서는 필수는 아니지만, 실제 운영 품질을 높이려면 등록하는 것이 좋습니다.

특히 고객 업무 용어, 약어, 화면명, 시스템명은 Synonym으로 정리해야 Intent 매칭과 Action 실행이 안정적입니다.

### 17.6 FAQ 및 답변 근거 관련 질문

#### Q. FAQ는 언제 등록하나요?

FAQ는 반복적으로 들어오는 질문이 있고, 운영자가 승인한 표준 답변을 제공하고 싶을 때 등록합니다.

FAQ는 `FAQ 관리` 화면에서 등록하며, Pack Export 시 `knowledge/faqs.json`에 포함됩니다.

#### Q. FAQ를 등록하면 Runtime에 바로 반영되나요?

바로 반영되지 않습니다.

FAQ 등록 후 Runtime에 반영하려면 다음 절차가 필요합니다.

1. FAQ 저장
2. Pack Builder에서 Draft 생성
3. Export ZIP 생성
4. Pack Repository에서 Import
5. Pack 검증
6. 승인
7. Active 전환
8. Runtime QA 확인

#### Q. FAQ 답변에는 어떤 내용을 넣어야 하나요?

FAQ 답변은 운영자가 사용자에게 그대로 안내해도 되는 수준으로 작성해야 합니다.

좋은 FAQ 답변은 다음 조건을 만족합니다.

- 첫 문장에서 핵심 답변을 제공합니다.
- 필요한 경우 화면 경로를 포함합니다.
- 작업 순서가 있으면 번호 목록으로 안내합니다.
- 추측이나 미확정 내용은 포함하지 않습니다.
- Source 근거가 있으면 Source ID나 문서명을 연결합니다.

#### Q. 답변 근거가 없다는 것은 무슨 뜻인가요?

답변 근거가 없다는 것은 챗봇이 질문에 답할 수 있는 Source 문서나 FAQ를 찾지 못했다는 뜻입니다.

이 경우 Source 문서를 추가하거나, 기존 문서 내용을 보강하거나, FAQ를 등록해야 합니다.

### 17.7 Action 관련 질문

#### Q. Action은 무엇인가요?

Action은 Intent가 매칭된 뒤 시스템이 실행할 동작입니다.

J-Brain에서는 화면 이동, 문서 검색, 정형 조회, 안내 응답, 개선 요청 생성 등을 Action으로 정의합니다.

#### Q. Action ID는 누가 정하나요?

현재는 운영자 또는 설계자가 규칙에 맞게 등록합니다.

권장 규칙은 다음과 같습니다.

- 화면 이동: `ACT-JB-GO-화면명`
- 문서 검색: `ACT-JB-SEARCH-DOC`
- 안내 응답: `ACT-JB-GUIDE-주제`
- 개선 요청: `ACT-JB-CREATE-REQUEST`

향후에는 화면에서 자동 생성하거나 표준 템플릿을 제공하는 방식으로 개선할 수 있습니다.

#### Q. NAVIGATE Action은 무엇인가요?

NAVIGATE Action은 사용자를 특정 관리자 화면으로 이동시키기 위한 Action입니다.

예를 들어 사용자가 “Pack Builder 화면으로 이동해줘”라고 질문하면, Runtime은 Pack Builder 화면으로 이동할 수 있는 Action Card를 반환할 수 있습니다.

#### Q. SEARCH_DOC Action은 무엇인가요?

SEARCH_DOC Action은 FAQ와 Source 문서를 검색하여 사용자의 질문에 대한 근거를 찾는 Action입니다.

J-Brain 사용법, 메뉴 설명, 운영 절차 같은 질문은 SEARCH_DOC Action으로 처리하는 것이 적절합니다.

#### Q. Action 실행 테스트는 무엇을 확인하나요?

Action 실행 테스트는 Intent가 연결한 Action이 실제 Runtime에서 실행 가능한지 확인하는 화면입니다.

현재 v0.1에서는 Action 테스트 진입점을 제공하며, 실제 결과는 Runtime QA와 Intent 매칭 테스트에서 함께 확인합니다.

### 17.8 Pack 관련 질문

#### Q. Pack은 무엇인가요?

Pack은 Runtime 챗봇이 동작하는 데 필요한 Intent, Example, Entity, FAQ, Action, 설정 파일을 묶은 배포 단위입니다.

고객 내부망에는 DB를 직접 연결하기보다 검증된 Pack을 반입하여 Runtime이 사용하도록 하는 구조를 권장합니다.

#### Q. Pack Builder는 무엇을 하나요?

Pack Builder는 DB에 저장된 Intent, Entity, FAQ, Action 정보를 읽어 표준 Intent Pack 구조로 변환합니다.

운영자는 Pack Builder에서 Draft를 생성하고, Export ZIP을 만들어 Pack Repository로 넘길 수 있습니다.

#### Q. Pack Export와 Pack Import는 무엇이 다른가요?

Pack Export는 DB 데이터를 ZIP 파일 형태의 배포 패키지로 만드는 작업입니다.

Pack Import는 생성된 ZIP을 Runtime Pack Store로 반입하고 Loader 검증을 수행하는 작업입니다.

#### Q. Pack 검증은 왜 필요한가요?

Pack 검증은 배포 전 대표 질문이 기대한 Intent와 Action으로 매칭되는지 확인하기 위해 필요합니다.

검증 없이 Pack을 활성화하면 잘못된 Intent 매칭, 잘못된 화면 이동, 답변 근거 누락이 발생할 수 있습니다.

#### Q. 승인되지 않은 Pack도 Active로 전환할 수 있나요?

아니요. 운영 정책상 승인되지 않은 Pack은 Active 전환할 수 없습니다.

Pack은 Import와 검증을 거친 뒤 승인되어야 Active Pack으로 전환할 수 있습니다.

#### Q. Rollback은 언제 사용하나요?

Active 전환 후 Runtime QA 또는 운영 중 문제가 발견되면 Rollback을 사용합니다.

Rollback은 직전 정상 Pack으로 되돌리는 기능입니다. Rollback 전후의 Pack 상태와 감사 로그를 확인해야 합니다.

### 17.9 Runtime QA 관련 질문

#### Q. Runtime QA는 무엇인가요?

Runtime QA는 실제 사용자가 질문했을 때 챗봇이 어떤 Intent를 매칭하고 어떤 Action과 답변을 반환하는지 확인하는 테스트 화면입니다.

운영 전 최종 검증 단계에서 반드시 사용해야 합니다.

#### Q. Runtime QA에서는 무엇을 확인해야 하나요?

다음 항목을 확인합니다.

1. Top Intent가 기대한 Intent인지
2. Confidence Label이 충분한지
3. Action ID가 올바른지
4. Action Card가 표시되는지
5. FAQ 또는 Source 근거가 표시되는지
6. 미응답으로 기록될 질문이 있는지

#### Q. Active Pack이 없다고 나오면 어떻게 하나요?

Pack Repository에서 Pack을 Import, 승인, Activate 했는지 확인해야 합니다.

Active Pack이 없더라도 기본 파일 Pack이나 DB Draft 확인 모드로 테스트할 수 있지만, 실제 운영 검증은 Active Pack 기준으로 수행하는 것이 좋습니다.

#### Q. Runtime QA 결과가 기대와 다르면 어떻게 하나요?

결과 유형에 따라 다음 화면에서 수정합니다.

- Intent가 다르면 `Intent 관리`
- 질문 표현이 부족하면 `Intent 상세`
- 용어 인식이 부족하면 `Entity/Synonym 관리`
- 답변 근거가 부족하면 `Source 관리` 또는 `FAQ 관리`
- Action이 없거나 틀리면 `Action 관리`
- Pack 반영이 안 되었으면 `Pack Builder`와 `Pack Repository`

### 17.10 운영 분석 및 개선 관련 질문

#### Q. 미응답 분석은 무엇인가요?

미응답 분석은 챗봇이 충분히 답하지 못한 질문을 모아 개선 대상으로 분류하는 기능입니다.

미응답 질문은 FAQ 후보, Intent Example 후보, Source 보강 후보, Action 추가 후보로 전환할 수 있습니다.

#### Q. 사용자가 답변이 틀렸다고 하면 어떻게 처리하나요?

다음 순서로 처리합니다.

1. Runtime QA 또는 로그에서 해당 질문을 확인합니다.
2. 실제 매칭된 Intent와 Action을 확인합니다.
3. 답변 근거 Source 또는 FAQ를 확인합니다.
4. 원인이 Intent인지, FAQ인지, Source인지, Action인지 분류합니다.
5. 개선 요청으로 등록합니다.
6. 다음 Draft Pack에 반영합니다.

#### Q. 새로운 질문 유형이 계속 들어오면 어떻게 하나요?

새로운 질문 유형이 반복되면 신규 Intent 또는 FAQ로 등록합니다.

단발성 질문이면 FAQ 후보로 보관하고, 반복 빈도와 업무 중요도를 기준으로 Pack 반영 여부를 판단합니다.

#### Q. 운영 중 FAQ만 수정하면 되나요?

질문에 따라 다릅니다.

답변 문구만 부족하면 FAQ 수정으로 충분할 수 있습니다. 그러나 질문이 잘못 분류되거나 Action이 잘못 실행된다면 Intent Example, Entity/Synonym, Action 연결까지 함께 수정해야 합니다.

### 17.11 시스템 및 권한 관련 질문

#### Q. 메뉴가 보이지 않으면 어떻게 하나요?

먼저 로그인한 계정의 역할과 메뉴 권한을 확인합니다.

시스템 관리자는 `권한 관리` 화면에서 역할별 메뉴 접근 권한을 확인할 수 있습니다.

#### Q. 사용자 계정은 어디서 관리하나요?

사용자 계정은 `시스템 관리 > 사용자 관리` 화면에서 관리합니다.

계정 생성, 수정, 상태 변경은 시스템 관리자 권한이 필요합니다.

#### Q. 감사 로그는 어디서 확인하나요?

감사 로그는 `운영/분석 > 감사 로그` 또는 `/admin/logs` 화면에서 확인합니다.

Pack Import, 승인, 반려, 활성화, Rollback 같은 주요 운영 이벤트는 감사 로그로 남기는 것을 원칙으로 합니다.

### 17.12 장애 응대 표준 문구

#### Q. 로그인 시 오류가 발생합니다.

로그인 오류는 백엔드 서버 상태, 인증 API 응답, DB 연결 상태를 먼저 확인해야 합니다.

브라우저 개발자 도구의 Network 탭에서 `/api/v1/auth/login/mock` 요청 상태를 확인하고, 백엔드 로그에서 500 오류 원인을 확인합니다.

#### Q. 프로젝트 목록을 불러오지 못합니다.

프로젝트 목록 API 또는 DB 연결 상태를 확인해야 합니다.

우선 `/api/v1/workflow/projects` 요청이 정상 응답하는지 확인하고, J-Brain 프로젝트 Source 또는 프로젝트 기준 데이터가 존재하는지 확인합니다.

#### Q. Pack Export가 실패합니다.

Pack Export 실패는 대개 필수 데이터 누락 또는 Pack Validation 오류 때문입니다.

Intent, Action, FAQ, Entity 데이터가 프로젝트 기준으로 정상 등록되어 있는지 확인하고, Export 결과의 Validation 오류 메시지를 먼저 확인합니다.

#### Q. Runtime QA에서 답변이 나오지 않습니다.

다음 항목을 순서대로 확인합니다.

1. Active Pack 존재 여부
2. Pack 선택 모드
3. Intent 매칭 결과
4. SEARCH_DOC 검색 결과
5. FAQ/Source 포함 여부
6. 미응답 로그 기록 여부

#### Q. 화면 이동 Action이 동작하지 않습니다.

Action 관리 화면에서 NAVIGATE Action의 `route_value`가 실제 프론트엔드 라우트와 일치하는지 확인합니다.

예를 들어 Pack Builder 화면은 `/admin/packs/builder` 경로를 사용합니다.

## 18. J-Brain 운영자용 FAQ 후보

아래 항목은 FAQ 관리 화면에 등록할 수 있는 초기 FAQ 후보입니다.

| --- | --- | --- |

| FAQ-JB-002 | 구축 워크플로우는 무엇인가요? | 구축 워크플로우는 기반 설정부터 운영 분석까지 챗봇 구축을 12단계로 안내하는 운영자용 절차 화면입니다. |
| FAQ-JB-003 | Source는 무엇인가요? | Source는 챗봇이 답변 근거로 사용할 원천 문서입니다. 등록 후 벡터화 작업이 완료되어야 검색에 사용할 수 있습니다. |

| FAQ-JB-008 | 미응답 분석은 왜 필요한가요? | 미응답 분석은 챗봇이 충분히 답하지 못한 질문을 찾아 FAQ, Intent, Source, Action 개선 후보로 전환하기 위해 필요합니다. |

## 19. 운영자 응대 예시

### 19.1 사용자: “J-Brain 사용법을 알고 싶어요.”

운영자 답변 예시는 다음과 같습니다.

J-Brain은 프로젝트별 챗봇을 구축하고 운영하기 위한 관리자 플랫폼입니다. 처음 사용하신다면 `구축 워크플로우 > 프로젝트 선택/목록`에서 프로젝트를 선택한 뒤, `1. 기반 설정`부터 `12. 운영 분석/개선`까지 순서대로 진행하시면 됩니다.

가장 먼저 확인할 화면은 `워크플로우 대시보드`, `Source 관리`, `Intent 관리`, `Pack Builder`, `Runtime QA`입니다.

### 19.2 사용자: “문서를 등록했는데 답변이 안 나와요.”

운영자 답변 예시는 다음과 같습니다.

문서 등록 후에는 벡터화 작업이 완료되어야 챗봇 검색에 사용할 수 있습니다. 먼저 `벡터화 작업 현황`에서 해당 Source의 작업 상태가 성공인지 확인해 주세요.

작업이 성공했다면 `검색 테스트`에서 같은 질문을 입력해 Source 근거가 검색되는지 확인합니다. 검색 결과가 없다면 문서 내용 보강, FAQ 등록, Synonym 추가가 필요할 수 있습니다.

### 19.3 사용자: “FAQ를 추가했는데 챗봇 답변이 바뀌지 않았어요.”

운영자 답변 예시는 다음과 같습니다.

FAQ는 저장 즉시 Runtime에 반영되지 않습니다. FAQ를 Runtime에 반영하려면 Pack Builder에서 Draft를 다시 생성하고, Export ZIP 생성, Import, 검증, 승인, Active 전환 과정을 진행해야 합니다.

Active 전환 후 Runtime QA에서 동일 질문을 다시 테스트해 주세요.

### 19.4 사용자: “Pack을 활성화할 수 없습니다.”

운영자 답변 예시는 다음과 같습니다.

Pack은 승인 상태가 되어야 Active 전환할 수 있습니다. Pack Repository에서 해당 Pack이 Runtime Store에 Import되었는지, 상태가 `validated` 또는 `approved`인지 확인해 주세요.

승인 전이라면 검증 결과를 확인한 뒤 Approve를 먼저 수행해야 합니다.

### 19.5 사용자: “챗봇이 엉뚱한 화면으로 이동합니다.”

운영자 답변 예시는 다음과 같습니다.

화면 이동 문제는 Intent와 NAVIGATE Action 연결을 확인해야 합니다. 먼저 Runtime QA에서 매칭된 Intent ID와 Action ID를 확인한 뒤, `Action 관리` 화면에서 해당 Action의 `route_value`가 올바른 화면 경로인지 확인해 주세요.

필요하면 Intent Example을 보강하거나 중복 Intent를 정리해야 합니다.
