# J-Brain 프로젝트별 격리 검증 체크리스트

## 목적

J-Brain이 프로젝트별 Source, Intent, Entity, Action, FAQ, Pack, Runtime 데이터를 독립적으로 관리하고, 사용자/권한/시스템 설정 같은 전역 기능은 프로젝트 선택과 분리되어 동작하는지 데모 시연 전후에 확인한다.

## 사전 조건

- 프로젝트 A: `J-Brain`
- 프로젝트 B: `Demo-Isolation` 또는 별도 테스트 프로젝트
- 두 프로젝트에 서로 다른 Source 1건 이상 등록
- 각 프로젝트에서 자동 후보 생성 또는 Intent/FAQ/Action 수동 등록을 최소 1건 이상 수행
- Pack Build 및 Pack Validation을 프로젝트별로 최소 1회 이상 실행

## 검증 원칙

- 상단 프로젝트 선택 드롭다운을 바꾸면 프로젝트형 화면은 선택한 프로젝트 기준 데이터만 표시되어야 한다.
- Runtime 응답은 현재 프로젝트의 Active Pack 또는 명시적으로 선택한 Pack 기준으로 동작해야 한다.
- Permission, 사용자 관리, 시스템 설정 등 시스템 전역 기능은 프로젝트 선택값으로 필터링되지 않아야 한다.

## 프로젝트별 격리 검증 항목

| No | 기능 | 검증 방법 | 기대 결과 |
|---:|---|---|---|
| 1 | Source 프로젝트별 격리 | 프로젝트 A/B를 전환하며 Source 목록을 확인한다. | 각 프로젝트에 등록된 Source만 표시된다. |
| 2 | 자동 후보 생성 프로젝트별 격리 | 프로젝트 A에서 신규 자료 분석 또는 전체 재분석을 실행한다. | A의 Source 기반 후보만 생성되고 B 후보 목록에는 섞이지 않는다. |
| 3 | Intent 목록 격리 | Intent 관리 화면에서 A/B를 전환한다. | 선택 프로젝트의 Intent만 표시되고 수정/보관도 해당 프로젝트에만 반영된다. |
| 4 | Entity/Synonym 목록 격리 | Entity/Synonym 관리 화면에서 A/B를 전환한다. | Entity Type, Synonym 항목이 프로젝트별로 분리되어 표시된다. |
| 5 | FAQ 목록 격리 | FAQ 관리 화면에서 A/B를 전환한다. | FAQ 질문/답변 목록이 프로젝트별로 분리된다. |
| 6 | Action 목록 격리 | Action 관리 화면에서 A/B를 전환한다. | Navigation, Query, API, Download Action이 선택 프로젝트 기준으로만 표시된다. |
| 7 | Pack Build 데이터 범위 | 프로젝트 A에서 Pack Builder를 실행하고 Export 결과를 확인한다. | A의 Intent, Entity, FAQ, Action만 Pack에 포함된다. |
| 8 | Pack Validation 검증 질문 범위 | 프로젝트 A에서 Pack Validation을 실행한다. | A의 활성 검증 질문만 실행되고 결과가 A 프로젝트에 저장된다. |
| 9 | Runtime Active Pack 독립성 | Pack Repository에서 A/B의 Active Pack을 각각 확인한다. | 각 프로젝트의 Active Pack ID/version이 독립적으로 관리된다. |
| 10 | Runtime 질의 응답 Pack 기준 | 같은 질문을 A/B Runtime QA에서 각각 실행한다. | 각 프로젝트의 Active Pack 또는 선택 Pack 기준으로 응답, Intent, Action, Evidence가 달라진다. |
| 11 | 미응답 분석 프로젝트별 기록 | 프로젝트 A Runtime에서 fallback 질문을 입력한 뒤 미응답 분석을 확인한다. | A의 미응답 로그에만 기록되고 B에는 표시되지 않는다. |
| 12 | Permission 및 전역 기능 분리 | 프로젝트 선택값을 바꾼 뒤 사용자/권한/시스템 설정 화면을 확인한다. | Permission, 사용자 관리, 시스템 설정은 프로젝트 선택과 무관하게 전역 데이터로 표시된다. |

## 시연 중 빠른 확인 포인트

- 프로젝트 선택 드롭다운 변경 후 Intent, FAQ, Action, Pack 화면의 건수가 함께 바뀌는지 확인한다.
- Runtime 진단 영역에서 Pack ID/version이 현재 프로젝트와 일치하는지 확인한다.
- Permission 화면에서는 Project/System badge가 표시되고, 프로젝트 선택값이 권한 목록을 필터링하지 않는지 확인한다.

## 실패 시 점검 순서

1. 상단 프로젝트 선택값과 URL의 `projectId` 또는 `project` query가 일치하는지 확인한다.
2. API 호출 경로에 선택 프로젝트 ID가 포함되어 있는지 브라우저 네트워크 탭에서 확인한다.
3. Pack Repository의 Active Pack이 해당 프로젝트 기준으로 활성화되어 있는지 확인한다.
4. Permission 또는 시스템 설정 화면에서 프로젝트 필터가 적용되는 코드가 추가되지 않았는지 확인한다.
