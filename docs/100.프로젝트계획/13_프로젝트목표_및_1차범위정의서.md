## 2. 추진 배경

기존 챗봇 프로젝트는 GraphRAG와 생성형 LLM 기반 지식 Q&A 구조를 중심으로 설계되었다. 그러나 본 프로젝트는 폐쇄망 환경, 외부 LLM 사용 제한, 보안 통제, 업무 Action 연계 필요성을 고려하여 Lightweight NLU 기반의 Intent/Entity/Action 처리 구조로 전환한다.

본 프로젝트는 외부 고객 협의형 프로젝트가 아니라 대표님 지시 기반의 내부 선행 프로젝트로 추진한다. 따라서 외부 고객 확인 대기 없이 내부 기준으로 1차 목표와 PoC 범위를 수립하고, 탄소중립플랫폼을 기준 서비스로 삼아 공통 플랫폼 구조와 서비스별 Intent Pack 표준을 검증한다.

## 4. 프로젝트 최종 목표

본 프로젝트의 최종 목표는 폐쇄망 환경에서도 외부 생성형 LLM 의존 없이 자연어 기반 업무 처리를 제공할 수 있는 공통 챗봇 플랫폼을 구축하는 것이다.

최종 목표는 다음과 같다.

1. 여러 서비스에 공통 적용 가능한 Lightweight NLU 기반 챗봇 플랫폼 구축
2. 서비스별 Intent Pack을 통해 업무 Intent, Entity, Action, SQL Template, 화면 Route를 독립 관리
3. 사용자 질문을 Intent와 Entity로 분석하고 승인된 Action으로 안전하게 라우팅
4. 자연어 SQL 생성 없이 사전 승인된 SQL Template 또는 내부 API만 실행
5. 문서/FAQ형 질문은 Hybrid Search 또는 Template 답변으로 처리
6. 미응답 질문, 피드백, Action 실행 로그를 기반으로 운영 개선 체계 마련
7. 폐쇄망 반입을 고려한 Pack Import, Validation, Rollback 구조 제공

## 5. 1차 목표

1차 목표는 운영 전체 기능 완성이 아니라, 공통 플랫폼 골격과 탄소중립플랫폼 기준 PoC를 통해 서비스별 확장 가능성을 검증하는 것이다.

```text
1차 목표
공통 NLU/Action 플랫폼 구조를 정의하고,
탄소중립플랫폼 Intent Pack v0.1을 기준으로
질문 분류, Entity 추출, Action 라우팅, Mock 응답까지 검증한다.
```

### 5.1 1차 목표 상세
| 구분 | 목표 |
|---|---|
| 표준화 | 서비스별 Intent Pack 표준 구조 수립 |
| 기준 서비스 | 탄소중립플랫폼 Intent Pack v0.1 구체화 |
| 공통 엔진 | Intent Matcher, Entity Extractor, Action Router의 PoC 구현 |
| Action 처리 | 문서/FAQ, 화면 이동, 조회형 Mock Action 처리 검증 |
| 운영 구조 | 미응답 질문 등록, Confidence 분기, Fallback 처리 기준 수립 |
| 확장성 | 광고 플랫폼, 한도 관리 시스템에 동일 Pack 구조 적용 가능성 확보 |

## 6. 1차 범위

1차 범위에는 기획/설계뿐 아니라 개발 PoC가 포함된다.

### 6.1 기획/설계 범위
| 구분 | 범위 | 산출물 |
|---|---|---|
| 프로젝트 기준선 | 목표, 1차 범위, 제외 범위 정의 | 프로젝트 목표 및 1차 범위 정의서 |
| Pack 표준 | 서비스별 Intent Pack 구조 정의 | Intent Pack 표준 정의서 |
| 기준 서비스 Pack | 탄소중립플랫폼 Intent 후보, Entity, Action 정의 | 탄소중립플랫폼 Intent Pack v0.1 |
| 아키텍처 | 공통 NLU/Action 플랫폼 구조 정의 | 공통 NLU/Action 아키텍처 정의서 |
| 데이터 구조 | Intent, Entity, Action, Pack Version 모델 정의 | 데이터 모델 개정안 |
| API 구조 | Intent Pack 관리, 매칭 테스트, Action 실행 API 정의 | API 명세 개정안 |
| 테스트 기준 | Intent/Entity/Action/Fallback 검증 기준 정의 | 테스트 시나리오 |

### 6.2 개발 PoC 범위
| 구분 | 범위 | 완료 기준 |
|---|---|---|
| Intent Pack Schema | Intent, Entity, Action, SQL Template, Screen Route JSON Schema 초안 | Pack 파일 구조 검증 가능 |
| Pack Loader | 탄소중립 Intent Pack v0.1 로드 | 서비스 ID 기준 Pack 로드 가능 |
| Intent Matcher | 예상 질문 기반 Intent 후보 매칭 | Top-1/Top-3 후보 반환 |
| Entity Extractor | Rule 기반 Entity 추출 | 공장/현장/기간/Scope/지표/Menu 추출 |
| Confidence Router | High/Medium/Low/Very Low 분기 | 실행/후보 제시/Fallback 분기 가능 |
| Action Router | Intent와 Action Registry 매핑 | Action ID 기준 실행 경로 선택 |
| Mock Query Action | 공장별 배출량, 전력 사용량, 미입력 현황 Mock 응답 | 실제 DB 없이 결과 카드 생성 |
| Document/FAQ Fallback | 문서/FAQ형 질문 템플릿 응답 또는 검색 Stub | 기준 안내형 답변 가능 |
| Navigation Action | 화면 이동 응답 Stub | 메뉴 이동 버튼 데이터 반환 |
| Unanswered Logging | 미분류 질문 기록 | 미응답 질문 목록 저장 또는 파일 기록 |
| Test Script | Validation Questions 기반 테스트 | 기대 Intent/Entity와 결과 비교 |

### 6.3 탄소중립플랫폼 1차 적용 범위
| 유형 | 포함 범위 |
|---|---|
| 문서/FAQ 안내 | 배출량 산정 기준, Scope 기준, 배출계수 기준, 용어 설명 |
| 화면 이동 안내 | 배출량 입력 화면, 보고서 화면 |
| 사용 방법 안내 | 배출량 등록 방법, 전력 사용량 입력 방법 |
| 조회형 Mock Action | 공장별 배출량 조회, 전력 사용량 조회, 데이터 미입력 현황 조회 |
| 오류 안내 | 권한 오류, 메뉴 접근 오류 안내 |
| 운영 개선 | 미응답 질문 등록, Fallback 기록 |

## 7. 1차 제외 범위

1차 목표에서 제외하거나 보류하는 범위는 다음과 같다.

| 구분 | 제외/보류 범위 | 사유 |
|---|---|---|
| 실제 DB 연동 | 고객 또는 운영 DB 직접 연결 | 1차는 구조 검증이 목적이며 실제 데이터 접근 정책 미확정 |
| 운영 SQL 확정 | 실 DB 기준 SQL Template 확정 | 테이블/권한/성능 기준 확인 전 |
| 실제 메뉴 ID 연동 | 운영 화면 URL/Menu ID 연동 | 화면 라우팅 정보 확정 전 |
| 엑셀 다운로드 | 조회 결과 엑셀 다운로드 운영 기능 | 다운로드 권한/마스킹/파일 보관 정책 필요 |
| 보고서 다운로드 | 운영 보고서 다운로드 | 보고서 생성 방식과 권한 정책 필요 |
| 데이터 등록 | 배출량/사용량 데이터 등록 | 변경성 Action으로 승인/감사 정책 필요 |
| 데이터 수정/삭제 | 배출량/사용량 데이터 수정/삭제 | 데이터 훼손 리스크 |
| 사용자 권한 변경 | 권한 부여/회수 자동 처리 | 보안상 관리자 직접 처리 대상 |
| 외부 LLM 연동 | OpenAI/Azure OpenAI/Gemini 등 외부 API 호출 | 폐쇄망 대응 원칙과 상충 |
| On-Prem LLM 도입 | 내부 LLM 모델 구축/운영 | 1차 PoC 이후 고도화 후보 |
| 전 서비스 Pack 완성 | 광고/한도 관리 시스템 전체 Intent 정의 | 1차는 탄소중립 기준 Pack 표준 검증 |
| 운영 배포 | 실제 사용자 대상 운영 오픈 | PoC 검증 이후 별도 이행 단계 |

## 8. 1차 완료 기준

1차 완료 기준은 다음과 같다.

| 항목 | 완료 기준 |
|---|---|
| Intent Pack 표준 | 서비스별 Pack 구조와 필수 구성 파일이 정의되어 있다. |
| 탄소중립 Pack | 탄소중립 Intent, Entity, Action, 질문셋 v0.1이 작성되어 있다. |
| 질문 분류 | 탄소중립 질문 30~50개를 Intent 후보로 분류할 수 있다. |
| Entity 추출 | 공장/현장/기간/Scope/지표/Menu 주요 Entity를 추출할 수 있다. |
| Action 라우팅 | Intent 결과에 따라 Search, Navigate, Query Mock, Fallback으로 분기할 수 있다. |
| Mock 응답 | 공장별 배출량, 전력 사용량, 미입력 현황에 대해 Mock 결과를 반환할 수 있다. |
| Fallback | 미분류 질문을 미응답 질문으로 기록할 수 있다. |
| 테스트 | Validation Questions 기준으로 기대 Intent/Entity와 실제 결과를 비교할 수 있다. |
| 확장성 | 광고 플랫폼, 한도 관리 시스템도 동일 Pack 구조로 확장 가능하다는 설계 근거가 있다. |
