# 다음 작업 프롬프트: 운영 피드백 및 미응답 개선 루프 v0.6

```text
$superpowers:subagent-driven-development

현재 구현된 JWP Intent Factory Pack 검증/승인 Workflow v0.5를 기준으로 다음 단계 구현을 진행해 주세요.

목표:
1. 미응답 분석 화면 v0.1을 구현합니다.
2. Runtime에서 발생한 fallback/low confidence 질문을 운영자가 조회할 수 있게 합니다.
3. 미응답 질문을 Intent 개선 후보로 전환할 수 있게 합니다.
4. 개선 요청 관리 화면 v0.1을 구현합니다.
5. 개선 요청을 상태별로 관리합니다.
   - 신규
   - 검토 중
   - Intent 반영
   - Pack 검증 대기
   - 완료
   - 보류
6. 개선 요청을 기존 Intent에 Example로 추가하거나 신규 Intent 후보로 등록할 수 있게 합니다.
7. 개선 요청 처리 이력을 Pack 개선 이력과 연결할 수 있는 기본 구조를 추가합니다.
8. 외부망 반출 금지 원칙을 유지하고, 고객 원문 데이터는 비식별/요약 필드만 개선 요청으로 전환합니다.

구현 순서:
1. 현재 Backend 테스트와 Frontend 빌드를 재실행하여 기준선을 확인합니다.
2. 미응답 질문 저장소를 확인하고 DB 기반 조회 API 또는 파일 기반 Adapter를 구현합니다.
3. 개선 요청 DB 테이블과 API를 추가합니다.
4. `/admin/operations/unanswered` 화면을 실제 목록/필터/개선 후보 전환 화면으로 구현합니다.
5. `/admin/operations/improvement-requests` 화면을 실제 상태 관리 화면으로 구현합니다.
6. 개선 요청에서 Intent Example 추가 또는 신규 Intent 초안 생성 기능을 구현합니다.
7. Pack 개선 이력 화면에 개선 요청과 Pack Version 연결 정보를 표시합니다.
8. WBS 및 개발 계획 문서에 완료 상태와 남은 리스크를 반영합니다.

수용 기준:
- 기존 Backend 테스트가 모두 통과해야 합니다.
- 신규 운영 피드백/개선 요청 API 테스트가 통과해야 합니다.
- `npm run build`가 통과해야 합니다.
- 미응답 질문을 화면에서 조회할 수 있어야 합니다.
- 미응답 질문을 개선 요청으로 전환할 수 있어야 합니다.
- 개선 요청을 Intent Example 또는 신규 Intent 초안으로 반영할 수 있어야 합니다.
- 고객 원문 데이터 외부 반출 없이 로컬/폐쇄망 운영 원칙을 유지해야 합니다.

제외 범위:
- 외부 LLM 기반 자동 Intent 생성
- 고객 원문 데이터 외부망 전송
- 다중 승인 결재선 완성
- 실제 고객 운영 DB Query 실행
- 전자서명/암호화

완료 후:
- 화면에서 확인 가능한 변경점과 테스트 기준을 한글로 요약해 주세요.
- 다음 단계 구현 프롬프트를 생성해 주세요.
```
